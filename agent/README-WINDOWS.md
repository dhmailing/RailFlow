# RailFlow Agent — Windows 실행 방법

RailFlow의 **실제** 좌석 조회와 예약은 이 프로그램이 담당합니다. 웹 화면은
조건을 전달하고 상태를 보여주는 역할만 합니다.

> 이 프로그램은 화면이 보이는 브라우저를 띄우고, **로그인은 사용자가 직접**
> 합니다. 아이디·비밀번호·OTP를 묻지도, 저장하지도 않습니다.
> **결제는 자동으로 하지 않습니다.** 예약이 되면 결제 직전에 멈춥니다.

---

## 준비물

- Windows PC
- **Node.js LTS** — https://nodejs.org 에서 "LTS" 버튼을 눌러 설치하고,
  설치 중 선택지는 기본값 그대로 두면 됩니다.
- 공식 예매 사이트 계정 (본인 계정)

---

## 1단계 — 설치 (처음 한 번만)

1. 이 저장소를 내려받아 압축을 풉니다.
2. `agent\scripts\1-설치.cmd` 를 **더블클릭**합니다.
3. 검은 창이 뜨고 몇 분 동안 파일을 내려받습니다. "설치가 끝났습니다"가
   보이면 아무 키나 눌러 창을 닫습니다.

설치가 안 될 때: 창에 `node` 를 찾지 못했다는 말이 나오면 Node.js가 아직
설치되지 않은 것입니다. Node.js를 설치하고 **PC를 다시 시작한 뒤** 1단계를
다시 하세요.

---

## 2단계 — 공식 화면 기록 (처음 한 번만)

RailFlow는 공식 예매 화면의 생김새를 **미리 알고 있지 않습니다.**
"매진"이 어떤 글자로 표시되는지, 예약 버튼 이름이 무엇인지 같은 것을
추측하지 않기 위해, 실제 화면에서 직접 읽어 기록합니다.

1. `agent\scripts\2-화면기록.cmd` 를 더블클릭합니다.
2. 공식 예매 화면 주소를 붙여넣고 Enter를 누릅니다.
3. 브라우저가 열립니다. **직접 로그인**하세요.
4. 조회 화면에서 **동탄 → 울산(통도사)** 를 검색해 결과 목록을 띄웁니다.
5. 검은 창으로 돌아와 **Enter** 를 누릅니다. (지금 화면이 기록됩니다)
6. 브라우저에서 **예약내역** 화면으로 이동합니다.
7. 검은 창에서 **Enter** 를 한 번 더 누릅니다.
8. `Ctrl+C` 로 끝냅니다.

기록되는 것: 화면의 글자 라벨, 버튼 이름, 방문한 주소
기록되지 않는 것: 비밀번호, 쿠키, 이름, 전화번호, 예약번호, 화면 원본

### 2-1단계 — 기록한 내용 확정하기

기록이 끝나면 이런 파일이 생깁니다.

```
%USERPROFILE%\.railflow-agent\profiles\sr-srt.profile.json
```

메모장으로 열면 `observed` 안에 화면에서 본 글자들이 많이 나오는 순서대로
정리돼 있습니다. 그걸 보고 위쪽의 빈칸을 채워 주세요.

```jsonc
{
  "operator": "",                  // 예: SR (SRT)  — 화면에 보이는 사업자명
  "host": "etk.srail.kr",          // 자동으로 채워져 있습니다
  "urls": {
    "searchEntry": "...",          // 자동으로 채워져 있습니다. 조회 화면 주소가 맞는지 확인
    "reservationList": "..."       // 예약내역 화면 주소가 맞는지 확인
  },
  "vocabulary": {
    "soldOut": ["매진"],                    // 매진을 뜻하는 글자 (여러 개 가능)
    "availableStandard": ["일반실"],        // 일반실 예약 가능을 뜻하는 글자
    "availableFirst": ["특실"],             // 특실 예약 가능을 뜻하는 글자
    "reserveControl": ["예약하기"],         // 예약 버튼에 쓰인 글자
    "reservationListLink": ["예약내역"],    // 예약내역 링크에 쓰인 글자
    "loginRequired": ["로그인"],            // 로그인이 필요할 때 나오는 글자
    "reservationSuccess": [],               // 예약 완료 화면에 나오는 글자
    "paymentDeadlineLabel": [],             // "결제기한" 처럼 기한 옆에 붙는 글자
    "reservationNumberLabel": []            // "예약번호" 처럼 번호 옆에 붙는 글자
  },
  "formFields": {
    "departure": "출발역",    // 조회 폼에서 출발역 칸의 이름
    "arrival": "도착역",
    "date": "출발일",
    "passengers": "인원",
    "submit": "조회하기"      // 조회 버튼에 쓰인 글자
  },
  "paymentScreenMarkers": [],   // 결제 화면에만 나오는 글자 (있으면 즉시 중단)
  "verified": false             // <-- 다 채웠으면 true 로 바꾸세요
}
```

> 위 예시의 한글 낱말들은 **예시일 뿐입니다.** 실제 화면에 그렇게 쓰여 있는지
> 확인하지 못했으니, 반드시 `observed` 에 나온 실제 글자로 채워 주세요.

마지막 줄의 `"verified": false` 를 `"verified": true` 로 바꾸고 저장합니다.
**채우기 전에는 감시가 시작되지 않습니다.**

제대로 채웠는지 확인하려면 `agent` 폴더에서:

```
node railflow-agent.mjs check
```

## 3단계 — 감시 시작

1. `agent\scripts\3-감시시작.cmd` 를 더블클릭합니다.
2. 창에 이런 내용이 나옵니다.

```
== RailFlow 로컬 Agent 실행 중 ==
  주소        : http://127.0.0.1:4319
  연결 코드   : a1b2c3   <- RailFlow 화면에 입력하세요
  대상        : SR (SRT) (etk.srail.kr)
  조회 주기   : 60초 (고정)
  모드        : 읽기 전용으로 시작합니다.
  로그 파일   : C:\Users\...\.railflow-agent\logs\agent-2026-09-24.log
```

3. 같은 PC의 브라우저에서 RailFlow를 엽니다.
   - 로컬에서 띄운 경우: `http://localhost:3000`
   - 배포본을 쓰는 경우에도 **같은 PC**에서 열어야 합니다.
4. **자동예약** 탭으로 갑니다. "실제 연동" 이라고 붉게 표시된 칸에 위의
   **연결 코드**를 입력하고 [연결] 을 누릅니다.
5. 예매 화면에서 감시할 후보 열차를 고른 뒤, 자동예약 탭에서
   [읽기 전용으로 감시 시작] 을 누릅니다.
6. 열린 브라우저에서 **직접 로그인**하고, RailFlow 화면의 [로그인 완료] 를
   누릅니다.

이제 60초마다 실제 좌석 상태를 읽어 화면에 보여줍니다.
**이 단계에서는 예약 버튼을 절대 누르지 않습니다.**

---

## 4단계 — 실제 예약 (읽기 전용으로 확인한 뒤에만)

조건에 맞는 좌석이 나오면 화면이 **예약 승인 대기** 로 바뀝니다.
날짜·구간·인원·좌석등급·후보 열차번호를 다시 보여주니 **꼼꼼히 확인**하고,
맞으면 [실제 예약 진행 검토] → [위 조건으로 실제 예약 승인] 을 누릅니다.

그 뒤 Agent가 하는 일:

1. 같은 조건의 기존 예약이 있는지 먼저 확인 (있으면 예약하지 않고 멈춤)
2. 좌석 상태를 한 번 더 확인
3. 예약 버튼을 **한 번만** 클릭
4. 예약내역을 다시 조회해 예약이 실제로 생겼는지 확인
5. 결제기한을 화면에서 읽음
6. 나머지 후보 감시를 즉시 중단
7. **결제 화면 앞에서 멈춤**

화면에 "예약 성공 · 결제 필요" 와 결제기한이 뜨면, **공식 예매 서비스에서
직접 결제**하시면 됩니다.

---

## 중단하는 방법

- RailFlow 화면의 **[중단]** 버튼 (가장 확실합니다)
- Agent 창에서 **Ctrl+C**
- `agent\scripts\4-중단.cmd`

이미 예약 버튼을 누른 뒤라면, 중단을 눌러도 곧바로 "취소"가 되지 않습니다.
예약이 실제로 생겼는지 먼저 확인한 뒤 결과를 알려 줍니다.
**예약을 자동으로 취소하는 기능은 없습니다.** 취소가 필요하면 공식 예매
서비스에서 직접 하셔야 합니다.

---

## 알아두실 점

- **Agent 창을 닫거나 PC가 절전에 들어가면 감시가 멈춥니다.** 화면을 꺼도
  계속 도는 서버 자동예약이 아닙니다.
- 조회는 60초마다 한 번입니다. 더 짧게 설정해도 30초 아래로는 내려가지
  않습니다.
- 보안문자·대기열·접근 제한·추가 인증이 나오면 **즉시 멈춥니다.** 우회하지
  않습니다.
- 화면이 바뀌어 열차를 확실히 식별하지 못하면 **클릭하지 않고 멈춥니다.**
  잘못된 열차를 예약하는 것보다 멈추는 게 낫기 때문입니다.

## 로그와 개인정보

로그 위치:

```
%USERPROFILE%\.railflow-agent\logs\agent-YYYY-MM-DD.log
```

개인정보가 남지 않았는지 직접 확인하려면 PowerShell에서:

```powershell
Select-String -Path "$env:USERPROFILE\.railflow-agent\logs\*.log" `
  -Pattern "password|cookie|jsessionid|\d{3}-\d{4}-\d{4}|@"
```

아무 것도 나오지 않아야 합니다. 로그를 지우려면 `logs` 폴더를 삭제하세요.

자세한 내용: [개인정보·세션 보호](../docs/V0.8-PRIVACY-SESSION.md)

## 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| `node` 를 찾지 못한다 | Node.js 설치 후 PC 재시작 |
| "프로필을 사용할 수 없습니다" | 2-1단계의 빈칸을 채우고 `verified: true` 로 바꿨는지 |
| 웹 화면에서 Agent를 못 찾는다 | Agent 창이 떠 있는지, **같은 PC**에서 열었는지 |
| "연결 코드를 입력해 주세요" | Agent 창에 새로 표시된 코드를 다시 입력 (재실행하면 바뀝니다) |
| "이미 실행 중인 Agent가 있습니다" | 다른 Agent 창을 먼저 닫기 |
| "화면 변경으로 중단" | 공식 화면이 바뀌었을 수 있습니다. 2단계를 다시 하세요 |
