# v0.5 개발환경 실행 방법 / 운영 연결 승인 항목

## 개발환경에서 취소표 감시 기능 켜기

```bash
pnpm dev
```

기본 실행만으로는 v0.5 기능이 전부 비활성 상태로 보인다(fail-closed 기본값). 로컬에서 끝까지 확인하려면 `.env.local`에 다음을 추가한다(실제 비밀값 아님, 모두 기능 플래그):

```bash
SEAT_AVAILABILITY_PROVIDER=mock
ENABLE_SEAT_WATCH_JOBS=true
ENABLE_MOCK_SEAT_SIMULATION=true
AUTH_STORE=memory
WATCH_STORE=memory
```

`AUTH_STORE`/`WATCH_STORE`는 검토 후 추가된 fail-closed 플래그다(§V0.5-SEAT-WATCH.md §7) — 이 둘을 `memory`로 켜지 않으면 회원가입·로그인과 감시 작업 등록·기기 등록이 로컬 개발 환경에서도 503으로 거부된다. `NODE_ENV=production`(예: `pnpm build && pnpm start`로 로컬 프로덕션 빌드를 띄운 경우)에서는 이 두 값을 `memory`로 설정해도 항상 사용 불가로 취급된다 — 실제 Postgres 연결 전까지는 프로덕션에서 계정도 감시 작업도 만들 수 없다는 것을 로컬에서도 그대로 재현하기 위함이다.

그 다음:

1. `/`(예매 탭)에서 마이페이지 탭으로 이동해 RailFlow 계정을 만든다(이메일·8자 이상 비밀번호 — 실제 코레일 계정이 아니다).
2. 자동예약 탭으로 이동하면 로그인된 상태로 감시 등록 폼이 보인다.
3. 알림 받을 곳(이메일 또는 텔레그램 chat id 아무 문자열)을 하나 등록하고 체크한다.
4. 역·날짜·후보 열차를 입력해 감시를 등록한다. 개발 환경에서는 후보 열차마다 Mock 시나리오(한 번 확인 후 좌석 발생 등)를 고를 수 있다.
5. "진행 중인 감시" 카드에서 "검증값 1~5" 버튼으로 Worker를 한 스텝씩 수동 진행한다: `REGISTERED → WATCHING → (좌석 없음, 반복) → SEAT_FOUND`.
6. 좌석 발생 카드에서 "코레일+에서 예매하기"(공식 웹으로 이동 + 조건 복사) 또는 "예매 완료"/"다시 감시"를 눌러 흐름을 끝까지 확인한다.

오프라인 테스트: `scripts/verify-seat-watch.cjs`(아래)가 네트워크 없이 같은 흐름을 자동으로 검증한다.

```bash
node scripts/verify-seat-watch.cjs
```

## 운영(Production) 연결 전 별도 승인이 필요한 항목

이 PR은 아래 중 어느 것도 실행하거나 생성하지 않았다 — 모두 사람의 명시적 승인이 있어야 다음 PR에서 진행한다.

1. **PostgreSQL 인스턴스 생성 및 연결** — 새 유료 인프라(관리형 Postgres)가 필요하다(`db/postgres/migrations/0001_init.sql` 참고).
2. **Vercel 환경변수 등록** — `SEAT_AVAILABILITY_PROVIDER`, `ENABLE_SEAT_WATCH_JOBS`, `ENABLE_MOCK_SEAT_SIMULATION`, `AUTH_STORE`, `WATCH_STORE`를 운영에서 켜는 것은 사람이 명시적으로 결정해야 한다(§v0.5 프롬프트 7번 원칙: 이번 단계에서 켜지 말 것). 특히 `AUTH_STORE=memory`/`WATCH_STORE=memory`는 운영(NODE_ENV=production)에서는 설정해도 항상 무시되므로, 실제 계정·감시 작업이 동작하려면 `postgres` 어댑터 구현이 먼저 필요하다.
3. **FCM 프로젝트 생성** — Firebase 프로젝트, `google-services.json`, 서버 발송 키.
4. **Web Push VAPID 키 발급**.
5. **텔레그램 봇 생성**(봇 토큰).
6. **이메일 발송 도메인 인증**(SPF/DKIM, 발신 서비스 선택).
7. **공식 좌석정보/예약 Provider 계약** — 코레일/SR/코레일+ 측과의 공식 API·서면 허용 없이는 `SeatAvailabilityProvider`의 실제 구현체를 추가하지 않는다.
8. **Android 서명 키·Play Console 계정** — TWA/Capacitor 전환 시.
