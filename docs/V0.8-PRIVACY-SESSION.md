# v0.8 개인정보·세션 보호

Local Automation Agent가 **무엇을 다루지 않는가**를 코드 위치와 함께
기록한다. 확인은 각 항목의 "검증" 줄에 적힌 방법으로 직접 할 수 있다.

---

## 1. 로그인

- 브라우저는 항상 **화면이 보이는(headed)** 모드로 뜬다. `headless` 는
  설정으로 끌 수 없다(`agent/src/config.mjs` 의 `headless: false` 는 상수).
- **사용자가 직접 로그인한다.** 자동화 코드는 아이디·비밀번호·OTP·보안문자를
  입력하지도, 읽지도, 저장하지도 않는다. Provider에는 그런 메서드 자체가
  없다(`provider-contract.mjs` 의 필수 메서드 목록 참조).
- RailFlow 웹 화면은 계정 정보를 묻지 않는다. "로그인 완료" 버튼만 있다.
- 로그인 완료 판정은 버튼을 눌렀다는 사실만으로 하지 않는다. 예약내역
  화면에 실제로 접근되는지 확인한다.

**검증**: `agent/` 전체에서 `type=password`, `fill(password`, `otp` 를
검색해도 입력 코드가 나오지 않는다. `scripts/verify-live-agent.cjs` 가
이 검사를 자동으로 수행한다.

---

## 2. 브라우저 프로필과 세션

- 첫 실증에서는 **임시 프로필**을 쓴다
  (`config.mjs: tempBrowserProfileDir()` → OS 임시 폴더 + PID + 시각).
- 브라우저를 닫으면 로그인이 남지 않아도 된다. 그게 의도다.
- **쿠키나 세션을 파일로 내보내지 않는다.** `storageState()`,
  `context.cookies()` 를 호출하는 코드가 없다.
- Provider 계약이 `exportCookies`, `saveSession` 이라는 이름을 금지한다.
- 로그인이 만료되면 `AUTH_REQUIRED` 로 전환하고 자동 클릭을 멈춘다.
  **자동 재로그인을 시도하지 않는다.** 사용자가 다시 로그인한 뒤 명시적으로
  재개해야 한다.

**검증**: `grep -rn "storageState\|cookies()\|setCookie" agent/` 가 비어 있다.

---

## 3. 로그에 남지 않는 것

모든 로그·IPC 응답·상태 저장은 `agent/src/redact.mjs` 를 거친다.

지워지는 것:

| 종류 | 처리 |
|---|---|
| 비밀번호·OTP·쿠키·토큰·Authorization | 키 이름만 남고 값은 `[REDACTED]` |
| 카드번호(13~19자리) | `[CARD_OR_LONG_NUMBER]` |
| 이메일 | `[EMAIL]` |
| 전화번호 | `[PHONE]` |
| 주민등록번호 형태 | `[NATIONAL_ID]` |
| 긴 무작위 문자열(32자 이상) | `[LONG_TOKEN]` |
| 사람 이름 | 첫 글자만 (`홍**`) |
| 예약번호 | 뒤 3자리만 (`********678`) |

예약번호를 완전히 지우지 않고 뒤 3자리를 남긴 이유: 사용자가 공식 화면의
예약내역과 대조할 수 있어야 하는데, 로그 파일에 원문이 남으면 안 되기
때문이다.

**DOM 전체나 HTML 원문은 어떤 경우에도 기록하지 않는다.** 화면에서 읽은
문구는 `safeScreenText()` 로 공백 정리 + 마스킹 + **120자 제한**을 거친 뒤에만
남는다.

**검증**: `tests/agent/redact.test.mjs` (6개), `tests/agent/runner.test.mjs` 의
"상태 스냅샷에 비밀번호·쿠키가 새어나가지 않는다".

## 4. 네트워크 경계

- Agent는 **프로필이 허용한 호스트 하나**로만 이동한다. 다른 호스트면
  `HOST_NOT_ALLOWED` 로 거부한다(`assertAllowedUrl`).
- `https` 가 아닌 주소로는 이동하지 않는다.
- 로컬 IPC 서버는 **`127.0.0.1` 에만** 바인딩한다. `0.0.0.0` 으로 열지 않는다.
- CORS는 `localhost` / `127.0.0.1` origin만 허용한다.
- **인증정보와 세션을 서버(Vercel)로 전송하지 않는다.** 웹 UI가 Agent에
  보내는 것은 조건(구간·날짜·인원·좌석등급·열차번호)뿐이고, Agent가
  돌려주는 것은 마스킹된 상태뿐이다. 그 사이에 서버는 없다.

---

## 5. 연결 코드(페어링 토큰)

- Agent를 실행할 때마다 **새로 생성**된다(`crypto.randomBytes(3)`).
- 파일로 저장하지 않는다.
- 웹 쪽에서는 `sessionStorage` 에만 둔다. 탭을 닫으면 사라지고, 서버로
  전송되지 않는다.
- 없으면 `/status`, `/jobs` 등 모든 명령이 401 이다. `/ping` 만 예외로,
  "Agent가 떠 있다"까지만 알려준다.

---

## 6. 스크린샷·CI

- Agent는 스크린샷을 자동으로 저장하지 않는다.
- 사용자가 실증 결과를 공유할 때는 아이디·이름·전화번호·예약번호를 가려야
  한다. 예약번호는 화면에서 뒤 3자리만 대조하면 된다.
- 콘솔과 CI 로그에 DOM 전체나 쿠키를 출력하지 않는다.
- 테스트 실행 시 `RAILFLOW_AGENT_QUIET=1` 이면 콘솔 출력을 끈다.

## 7. 로그 위치와 확인 방법

```
%USERPROFILE%\.railflow-agent\logs\agent-YYYY-MM-DD.log
```

한 줄에 JSON 하나다. 개인정보가 남지 않았는지 직접 확인하려면 Windows
PowerShell에서:

```powershell
Select-String -Path "$env:USERPROFILE\.railflow-agent\logs\*.log" `
  -Pattern "password|cookie|jsessionid|\d{3}-\d{4}-\d{4}|@"
```

아무 것도 나오지 않아야 한다. 무언가 나온다면 그 줄을 공유하기 전에
지우고, 문제를 알려 주기 바란다.

로그 파일을 지우려면 `.railflow-agent\logs` 폴더를 통째로 삭제하면 된다.
