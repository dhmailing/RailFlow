# 실제 잔여좌석 조회 연동 가능성 조사

최초 2026-09-22 · **개정 4판 2026-09-23** · 대상: RailFlow 실제 좌석 조회

## 0. 결론

**TAGO 경로는 확정적으로 종료됐다. 다음 후보는 실제 예매 화면 읽기 전용 조회이며, 지금은
사용자가 직접 조회한 화면을 확보하는 단계다.**

- 승인받은 TAGO 열차정보 서비스에는 **좌석 기능이 없다**는 것이 공식 명세로 확인됐다(§1).
  이 건에 대한 조사는 종료한다. 추가 조사·문서 전면 개정을 반복하지 않는다.
- 다음 후보는 실제 예매 화면을 읽기 전용으로 조회하는 방식이다. **기술적으로 불가능하다고
  판정된 것이 아니고, 외부 이용 조건이 금지한다고 확인된 것도 아니다** — 세 축(프로젝트 지침 /
  외부 이용 조건 / 기술적 접근 가능성)을 §3에서 구분해 정리했다.
- 현재 단계: §5의 **화면 확보**. 화면을 받은 뒤에만 다음 구현의 최소 조건을 제시한다.
  선택자·파서 코드는 만들지 않았다.

## 1. 확정 — TAGO 열차정보의 기능 범위 (조사 종료)

사용자가 공공데이터포털 「국토교통부_(TAGO)_열차정보」 상세 페이지의 API 목록과 응답 예시를
캡처로 제공했다. 확인 수준: **사용자 제공 공식 페이지 캡처**.

**제공되는 기능 — 4개가 전부다.**

| 오퍼레이션 | 기능 | 좌석 관련 |
|---|---|---|
| 출발·도착지 기반 열차정보 조회 | 구간·날짜 기준 열차 목록 | 없음 |
| 시·도별 기차역 목록 조회 | 역 목록 | 없음 |
| 차량 종류 목록 조회 | 열차 종별 코드 | 없음 |
| 도시 코드 목록 조회 | 도시 코드 | 없음 |

**열차정보 조회 응답 항목 — 7개가 전부다.**

`trainno`(열차번호) · `traingradename`(열차 종류) · `depplandtime`(출발 예정시각) ·
`arrplandtime`(도착 예정시각) · `depplacename`(출발역 이름) · `arrplacename`(도착역 이름) ·
`adultcharge`(성인 운임)

`totalCount`는 **검색 결과 건수이며 잔여좌석 수가 아니다.**

**따라서 이 TAGO 서비스의 공개 명세에는 다음이 없다**: 잔여좌석 수, 좌석등급별 예약 가능 상태,
예약 생성, 예약내역 조회, 예약 취소, 결제.

범위 제한 — **이 서비스에 한정된 결론이다.** 다른 공개 API·다른 제공 주체까지 없다고 확대
해석하지 않는다.

부가 확인: `gateway_swagger_guide.pdf`는 공공데이터포털 **공통 사용 안내서**이며 열차정보 전용
명세가 아니다. 이 문서로 좌석 기능 유무를 판단하지 않는다.

이전 판들이 이 항목을 "미확인"으로 둔 것은 이 근거로 **정정한다.** 우리 구현이 7개 중 5개만
읽는 것(역 이름 2개 미사용)은 결함이 아니다 — 화면에 필요한 값만 매핑한 것이며, 응답에 좌석
항목이 없다는 사실과는 무관하다.

**TAGO 승인·인증키·운영 등록은 이미 완료되어 있다**(승인, 활용기간 2026-09-19~2028-09-19,
운영 환경 키 등록, 운영 시간표·운임 반환 화면 사용자 제공). 활용신청·키 발급을 다시 요구하지
않는다. **조사 세션의 키 접근 불가는 운영 키 미등록과 다른 사안이다.**

TAGO 시간표·운임 구현은 그대로 유지한다.

## 2. 다음 후보 — 실제 예매 화면 읽기 전용 조회

최종 사용자 흐름: 조건 선택 → 사용자가 로그인 준비 → 자동 좌석 조회 → 조건에 맞는 좌석 발견 →
자동 예약 → **사용자가 직접 결제**. 이번 단계 범위는 **로그인 준비와 좌석 조회까지**이며,
구매·예약·결제 버튼은 누르지 않는다.

착수 전에 확인해야 할 항목 — **전부 미확인**이다(이 환경에서 대상 사이트에 접근할 수 없다).

| # | 확인 항목 | 상태 |
|---|---|---|
| 1 | 동탄↔울산(통도사)를 실제로 제공하는 **예매 주체**와 **현재 공식 예매 주소** | **미확인** |
| 2 | 현재 이용 조건에서 이 자동화에 적용되는 조항 | **미확인** |
| 3 | 로그인 전/후 각각 좌석 조회가 어디까지 되는지 | **미확인** |
| 4 | 사용자가 직접 로그인한 브라우저에서 조회를 이어갈 수 있는지 | **미확인** |
| 5 | 날짜·역·열차번호·출발시각으로 원하는 열차를 특정할 수 있는지 | **미확인** |
| 6 | 일반실·특실 각각의 표시 상태(예약 가능/매진/예약대기 등 실제 문구) | **미확인** |
| 7 | 로그인 만료·추가 인증·접근 제한·조회 실패를 서로 구분할 수 있는지 | **미확인** |

1번 관련 저장소 사실: RailFlow는 이미 `https://www.korail.com/`을 공식 예매 링크로 사용한다
(`lib/watch/booking-launch-provider.ts` 등, **확인됨**). 다만 이것이 **이 구간의 올바른 예매
주체인지는 별개 문제이며 미확인**이다. 과거 보고서에 나온 코레일·SR 통합 시행일이나 앱 명칭은
원문 검증 전까지 전제로 쓰지 않는다.

원칙:
- 공식 API가 없다는 이유만으로 화면 자동화가 **기술적으로 불가능**하다고 단정하지 않는다.
- 화면에 접근된다는 사실을 **자동화 허용이나 예약 성공의 근거**로 삼지 않는다.
- 실제 화면·선택자·결과를 추측해 구현하지 않는다. 확인되지 않은 선택자를 채운 코드를
  "실제 연동 완료"로 제출하지 않는다.

## 3. 프로젝트 지침 충돌 — 사용자 결정 필요

기술적 한계가 아니라 **지침 충돌**이다. 지침을 임의로 완화하거나 삭제하지 않았다.

### 세 가지 축을 섞지 않는다

이 셋은 서로 다른 문제이며, 하나가 미확인이라고 다른 하나가 결정되지 않는다.

| 축 | 현재 상태 |
|---|---|
| **프로젝트 지침** (`CLAUDE.md`) | 조항 A가 공식·승인된 연동 확인 전 구현을 제한한다 — **적용 중** |
| **외부 서비스 이용 조건** | 해당 화면 자동화가 허용되는지 **확인하지 못했다**(허용도 금지도 확인 안 됨) |
| **기술적 접근 가능성** | 이 조사 환경에서는 대상 사이트에 접근할 수 없어 **확인 불가**. 사용자의 일반 브라우저에서는 화면 열람이 가능하다 |

**지침을 바꾼다고 외부 이용 조건을 충족한 것이 되지 않는다.** 반대로 외부 조건이 허용이더라도
조항 A가 그대로면 구현은 여전히 제한된다.

### 충돌 A — 승인된 연동 방식 요건 (이번에 변경하지 않음)

**조항**(`CLAUDE.md` 현재 목표 v0.3 §4): *"좌석 잔여·예약 기능은 공식·승인된 연동 방식이
확인된 뒤 별도 구현한다."*

- **이 조항 때문에 할 수 없는 것**: 예매 화면 읽기 전용 조회 기능의 **구현 착수**.
  **현재 해당 화면 자동화의 허용 여부를 확인하지 못했으므로**(= "승인된 방식이 아니다"라고
  판정된 것이 아니다) 조항 A의 "확인된 뒤" 요건을 아직 충족하지 못한 상태다.
- **상태**: 이 조항은 **변경하지 않는다**(사용자가 이번 메시지에서 유지하기로 명시).
- **해제 조건**: 해당 사이트의 이용 조건에서 이 방식의 허용 여부가 **확인**될 것.
  확인 결과가 "허용"이면 조항 A를 충족하고, "불가"면 이 후보를 접는다.

### 충돌 B — 실행 환경 전제 (이번에 정정됨)

**정정 전 조항**: *"사용자는 개인 PC가 아니라 iPad를 사용한다."* → 사실과 달라 정정했다.

**정정 후**(`CLAUDE.md` 사용자 환경): 사용자는 **iPad와 Windows PC를 함께 사용한다.**
다만 **PC에 설치·터미널 실행이 가능한지는 미확정이므로 설치 가능한 개발 환경으로 가정하지
않는다.** 기본값은 설치·터미널 없이 진행하는 것이고, 꼭 필요하면 요구 전에 가능한지 먼저
확인한다.

- **지금도 제한되는 것**: 로컬 브라우저 자동화(Playwright 등)를 **전제로 한 검증 안내**.
  설치·터미널 가능 여부가 확정되지 않았으므로 기본 경로로 삼지 않는다.
- **지침 안에서 가능한 것**: 사용자가 **iPad 또는 PC의 일반 브라우저로 직접** 공식 예매 화면을
  열어 §2 항목을 확인하고 화면을 공유하는 것. 설치·터미널·서버가 필요 없다. → §5
- **남은 확인 사항**: PC에서 설치·터미널 실행이 가능한지(가능하다면 선택지가 넓어지지만,
  조항 A와는 별개 문제다).

### 충돌 C — 로그인 세션 취급 (구분이 중요)

**조항**(`CLAUDE.md` 개발 원칙): *"비밀번호, 카드정보, OTP, 쿠키를 요청하거나 저장하지 않는다."*

| 방식 | 지침 부합 |
|---|---|
| 사용자가 자기 브라우저에 **직접 로그인**하고, 그 브라우저가 메모리에 유지하는 세션으로 같은 브라우저에서 조회를 이어감 | **부합** — 자격증명을 요구하지도, 저장하지도 않는다 |
| 세션·쿠키를 **파일로 추출·보관**(예: 브라우저 자동화의 storageState 저장) | **위반** — 쿠키 저장에 해당 |
| 비밀번호·OTP를 채팅·코드·환경변수로 전달 | **위반** |

→ 읽기 전용 검증을 한다면 **첫 번째 방식만** 허용된다. 비밀번호·OTP·쿠키를 채팅으로 요구하지
않으며, 저장소·로그·스크린샷·브라우저 추적 파일에도 기록하지 않는다.

### 충돌 D — 조회 빈도

**조항**: *"과도한 반복 조회, 중복 예약, 무제한 재시도를 구현하지 않는다."*

→ 시뮬레이터의 1~5초 간격을 실제 사이트에 그대로 적용하지 않는다. 처음에는 **단건 조회**로만
검증하고, 반복 조회는 이용 조건과 요청 제한을 확인한 뒤 별도 설계한다.

### 공통 금지 (결정 대상 아님)

CAPTCHA·대기열·속도 제한·접근 제한 우회, 탐지 회피, 계정·IP 교체, 비공개 API 추측은 어떤
결정에서도 구현하지 않는다.

## 4. 이 환경의 제약

- 이 컨테이너는 한국 철도·공공데이터 도메인에 접근할 수 없다(egress 정책). 설치된 브라우저
  (Playwright/Chromium)도 동일하게 차단된다. **반복 요청하거나 우회하지 않았다.**
- 따라서 이 세션에서는 실제 예매 화면의 구조·선택자·표시 문구를 **확인할 수 없다.**
- 조사 환경에 TAGO 키가 없는 것은 조사 환경만의 제약이며, 운영 환경에는 등록되어 있다.

## 5. 실제 예매 화면 분석 준비

사용자가 **일반 브라우저**(iPad 또는 PC)에서 직접 조회한 화면을 근거로 §2의 항목을 채운다.
설치·터미널·서버가 필요 없다. 로그인이 필요하면 **사용자가 직접 입력한다** —
비밀번호·OTP·쿠키는 요청하지도, 기록하지도 않는다.

### 5-1. 화면에서 정리할 항목

받은 화면마다 아래를 그대로 기록한다. **추측해서 채우지 않는다.**

| # | 항목 | 기록 방식 |
|---|---|---|
| 1 | **실제 접속 사이트와 검색 구간** | 주소창의 도메인, 출발·도착역, 조회한 날짜 |
| 2 | **로그인 전후 여부** | 이 화면이 비로그인 상태인지 로그인 후인지 |
| 3 | **열차번호·날짜·출발시각** | 목록에 함께 표시되는지, 표시 형식은 어떤지 |
| 4 | **일반실·특실의 표시 상태** | 각 등급 칸에 실제로 뜬 문구 그대로(숫자인지 말인지) |
| 5 | **예약 가능·매진·예약대기 등의 구분** | 등장한 상태 표현을 빠짐없이, 화면 문구 그대로 |

추가로 보이면 함께: 좌석 수가 숫자로 나오는지 여부, 조회 시각 표시 유무,
"조회할 수 없음"류의 실패 표시 문구.

### 5-2. 공유 방법

해당 화면의 **캡처**면 충분하다. 로그인 입력값·개인정보·예약번호가 보이지 않는 범위로
잘라서 주시면 된다. 여러 상태(예약 가능한 열차와 매진된 열차)가 한 화면에 같이 보이면
가장 좋다.

### 5-3. 이 단계가 아닌 것 (명확히)

- 화면을 수동으로 확인하는 것은 **자동화 구현이 아니다.**
- 화면이 열린다는 사실은 **자동화 허용 여부의 검증이 아니다**(§3의 세 축 참조).
- 따라서 이 단계가 끝나도 "실제 연동 검증 완료"로 보고하지 않는다. 화면을 확보한 **뒤에만**
  다음 구현에 필요한 최소 조건을 제시한다.
- 새 데모나 추측한 선택자 코드는 만들지 않는다.

## 6. 예약 단계로 넘길 항목

실제 좌석 조회가 확인된 **뒤에** 정리한다. 지금은 전부 미확인이다.

- 동일 열차·날짜·구간·인원·좌석등급의 일치 확인 방법
- 예약 버튼 클릭과 **실제 예약 성공**을 구분하는 근거
- 예약번호와 **실제** 결제기한 확인 방법
- 결과가 불명확할 때 **재클릭 전에** 예약내역을 확인하는 방법
- 하나의 예약 성공 후 나머지 후보를 중단하는 방식

**시뮬레이터의 Mock 예약번호(`RF-XXXXXXXX`)와 10분 결제기한을 실제 정책으로 쓰지 않는다.**

## 7. 확인 수준 분류

- **확인됨** — 이 세션에서 저장소 코드·이력을 직접 열람.
- **사용자 제공 증거** — 사용자가 공식 화면 캡처·기록으로 제공. 이 세션에서 재현하지 않았다.
- **잠정 정보** — 검색 요약만 확인. 원문 미열람. 판단 근거로 쓰지 않는다.
- **미확인** — 확인하지 못함. *존재하지 않음을 뜻하지 않는다.*

   코드를 만들지 않는다.

   허용 여부가 확인되는 것이다. 지침 변경만으로 외부 이용 조건이 충족되지는 않는다.
5. 그 전까지 `SEAT_AVAILABILITY_PROVIDER`는 `disabled`로 유지한다.
