# 실제 잔여좌석 조회·예약 연동 가능성 조사

최초 작성 2026-09-22 · **개정 2판 2026-09-22**(1판의 과잉 결론 정정) · 대상: RailFlow 실제 좌석 조회·예약

## 0. 결론

**원문 자료 확보 필요.**

이번 조사만으로는 어떤 연동 방식도 "채택 가능" 또는 "채택 불가"로 판정할 수 없다. 판정에 필요한
**공식 원문을 한 건도 열람하지 못했기 때문**이다(§3). 따라서 이 문서는 "무엇이 가능한지"를
결론짓지 않고, **무엇이 확인됐고 무엇을 확인해야 하는지**만 기록한다.

실제 좌석 조회는 구현하지 않았고, 코드도 추가하지 않았다. 기존 fail-closed 기본값도 그대로다.

## 1. 1판에서 정정한 내용

1판(커밋 `a53cdb3`)은 확보한 근거보다 강한 결론을 냈다. 아래와 같이 정정한다.

| 1판 서술 | 문제 | 2판 분류·서술 |
|---|---|---|
| "운영자 허용 웹·앱 자동화 = **제외**" | 매크로 차단 보도는 *무단 자동화를 차단한다*는 사실이다. 여기서 *운영자가 허용하는 자동화·사용자 위임 경로가 존재하지 않는다*는 별개 명제를 도출할 수 없다 | **근거상 지원하지 않음** → 재분류: 허용 경로의 존재 여부는 **미확인**. 무단 자동화·탐지 회피를 하지 않는다는 원칙만 유효 |

| 코레일·SR 통합일(2026-09-01), 앱 명칭("코레일+")을 문서 곳곳의 전제로 사용 | 원문 미검증 보도를 전제로 파생 추론(대상 구간 영향, 기존 자료 무효화 등)을 전개했다 | **잠정 정보**로만 남기고, 이에 기댄 파생 추론은 삭제. 확인 항목으로만 유지 |

## 2. 확인 수준 분류 기준

- **확인됨** — 이 세션에서 원문/코드를 직접 열람해 확인. 재현 가능.
- **잠정 정보** — 검색 결과의 제목·요약만 확인. 원문 미열람. 판단 근거로 쓰지 않음.
- **미확인** — 확인하지 못함. *존재하지 않음을 뜻하지 않는다.*
- **근거상 지원하지 않음** — 그런 주장을 했으나 확보한 근거가 뒷받침하지 않음(1판 정정 항목).

## 3. 자료 접근 수단 점검

| 도구 | 결과 |
|---|---|
| 웹 검색 | **동작함**. 단, 돌려주는 것은 제목·URL·요약뿐이며 원문이 아니다 |
| HTTP 페치 / `curl` | 대상 도메인 전부 **CONNECT 403**(egress 정책) |
| 브라우저(Playwright + Chromium, 이 환경에 설치됨) | 동일하게 차단 — `net::ERR_TUNNEL_CONNECTION_FAILED` (2026-09-22 확인) |

차단이 확인된 도메인: `www.data.go.kr`, `apis.data.go.kr`, `info.korail.com`, `openapis.korail.com`,
`data.kric.go.kr`, `www.letskorail.com`, `etk.srail.kr`, `www.korea.kr`, 주요 언론사, `en.wikipedia.org`,
`www.scribd.com`.

동일 요청을 반복하지 않았고, 프록시 등으로 접근 통제를 우회하지 않았다.
**결론: 이 환경에서는 어떤 도구로도 공식 원문을 열람할 수 없다.**

  요청 제한 우회·차단 회피용 계정·IP 전환을 구현하지 않는다(`CLAUDE.md` 및 작업 지침).

**제3자 자료 취급**: GitHub의 비공식 래퍼·매크로 프로젝트는 조사 단서로만 참고한다.
존재·동작 여부가 허용 여부의 근거가 되지 않으며, 비공개 API 추측은 `CLAUDE.md`가 금지한다.
채택하지 않는다.

## 5. 이 세션에서 **확인됨**으로 기록할 수 있는 것

전부 이 저장소 코드·이 환경에 대한 사실이다. 외부 API의 명세가 아니다.

- `lib/rail/tago-provider.ts`가 `https://apis.data.go.kr/1613000/TrainInfo`의
  `GetStrtpntAlocFndTrainInfo`, `GetCtyAcctoTrainSttnList`를 호출한다.
- 그 응답에서 **우리 구현이 읽는 필드**는 `depplandtime`, `arrplandtime`, `traingradename`,
  `adultcharge`, `trainno` 5개다. *API가 이 5개만 반환한다는 뜻이 아니다 — 응답 항목 전체 목록은
  미확인이다.*
- 모든 결과에 `availability: "unknown"`이 들어간다. 즉 **RailFlow는 현재 좌석 상태를 표시하지 않는다.**
- `scripts/verify-rail.cjs`의 픽스처도 같은 5개 필드만 사용하며, 실제 API 호출 테스트는
  `"NOT RUN — fresh secret required"`로 표시된다. → **이 프로젝트는 TAGO 실호출을 한 번도
  라이브로 검증한 적이 없다.**
- 이 세션에 `DATA_GO_KR_SERVICE_KEY`가 설정되어 있지 않다.
- fail-closed 기본값: `SEAT_AVAILABILITY_PROVIDER=disabled`, `ENABLE_SEAT_WATCH_JOBS=false`,
  `SEAT_AUTOMATION_PROVIDER=unavailable`.
- §3의 네트워크 차단 사실.

않으며, 조건 부족을 Mock이나 코드 기반 추가로 대체하지 않는다.

## 7. 사용자가 확보해야 할 자료 (3건)

브라우저로 열람 후, 해당 부분을 캡처하거나 파일로 내려받아 공유해 주시면 된다.

### 자료 1 — 공공데이터포털: TAGO 열차정보 상세 페이지
- URL: `https://www.data.go.kr/data/15098552/openapi.do`
- **무엇을 확인하기 위한 자료인가**: 후보 A에서 **좌석 관련 항목이 응답에 있는지 없는지 확정**.
- 봐야 할 것: ① 오퍼레이션 목록 전체 ② 각 오퍼레이션의 **출력(응답) 항목 표 전체**
  ③ 첨부된 활용가이드 문서(있으면 파일째로) ④ 호출 제한·활용신청 조건
  ⑤ 페이지에 "호출중지/대체서비스" 공지가 걸려 있는지와 대체 서비스 이름

### 자료 2 — 한국철도공사 오픈API 포털: 제공 서비스 목록과 신청 절차
- URL: `https://openapis.korail.com/` (검색에서 확인된 샘플 경로: `/samples/public/run`)
- **무엇을 확인하기 위한 자료인가**: 코레일 자체 API에 **좌석 조회 또는 예약 서비스가
  포함되는지**, 그리고 **개인 개발자가 신청 가능한지**.
- 봐야 할 것: ① 제공 서비스 전체 목록(이름만이라도) ② 신청 자격·절차 ③ 좌석/예약 관련
  서비스의 유무 ④ 이용 조건

### 자료 3 — 한국철도공사 문의·제휴 창구 안내 페이지
- 출발점: `https://info.korail.com/` (공공데이터/고객센터 메뉴)
- **무엇을 확인하기 위한 자료인가**: 후보 B·C를 물어볼 **실제 접수 창구**를 확정.
  (현재 문서의 문의 창구는 **미확인**이며, 연락처를 추측해 적지 않는다.)
- 봐야 할 것: ① 공공데이터/오픈API 담당 부서와 문의 방법 ② 제휴·판매대행 문의 창구
  ③ 개발자·사업 제휴 관련 안내 페이지 유무

> 참고: 검색 요약에 TAGO 운영팀 전화번호로 보이는 값이 나타났으나 **원문 미검증**이라
> 이 문서에 확정 정보로 싣지 않는다. 자료 1·3의 공식 페이지에서 확인 후 사용.

## 8. 실제 예약 단계 설계에 필요한 확인 항목

연동 방식이 정해지기 전이라 **전부 미확인**이다. 명세 확보 시 이 순서로 확인한다.

| 항목 | 확인할 내용 |
|---|---|
| 예약 생성 vs 최종 구매·결제 | 좌석을 잡아두는 단계와 결제로 확정하는 단계가 분리되는지, 분리된다면 각각의 API와 상태값 |
| 예약 성공 식별자 | 성공 응답이 돌려주는 식별자와 그 유효 범위 |
| 응답 유실 시 확인 | 요청은 갔으나 응답을 못 받은 경우 예약내역을 재조회할 수단이 있는지 (없으면 중복예약 방지 설계 자체가 성립하지 않음) |
| 재시도·중복 방지 | 멱등키 지원 여부. 없으면 "재조회로 확인 후 판단"이 유일한 안전책 |
| 결제기한의 출처 | 실제 정책값과 그 값이 응답에 포함되는지. **현재 시뮬레이터의 10분은 RailFlow 자체 Mock 값이며 실제 정책값이 아니다** |
| 성공 후 다른 후보 중단 | 클라이언트 책임. 시뮬레이터에 이미 구현되어 있음 |
| 사용자 중지 시 처리 중 요청 | 취소 수단과 그 시한. 없으면 "이미 나간 요청은 되돌릴 수 없음"을 UI에 명시해야 함 |
| 서버 상시 실행 vs 기기 실행 | 아래 참조 |

**실행 주체에 대한 현재 사실**: 현재 RailFlow의 자동화는 **브라우저가 열려 있는 동안 반복
호출하는 방식**이며, 공개 시연과 서버 기반 작업 양쪽 모두 그렇다. 이를 "상시 서버 감시"라고
표현하지 않는다. 화면을 닫아도 이어지는 감시가 필요하다면 별도의 상시 실행 주체가 필요하다.
다만 **그것이 반드시 유료 인프라여야 한다고 단정하지 않는다** — 사용자 소유 상시 구동 기기,
Android 기기의 백그라운드 실행, 기존 보유 서버 등 선택지가 있으며, 어느 것이 적절한지는
연동 방식과 허용되는 호출 빈도가 정해진 뒤에 판단한다.

## 9. 문의문 초안 (중립 표현 · 전송하지 않음)

> 접수 창구가 **미확인**이므로 수신처를 비워 둔다. §7 자료 3으로 창구를 확인한 뒤 보낸다.
> 연락처를 추측해 적지 않는다.

### 9-1. 현재 운영 주체·예매 체계·연동 창구 확인

> 제목: 철도 승차권 조회·예매 연동 관련 문의 (운영 체계 및 담당 창구 확인)
>
> 안녕하십니까. 열차 조회·예매를 돕는 개인 개발 프로젝트를 준비하며,
> 공식적으로 허용되는 연동 방식을 확인하고자 문의드립니다.
>
> 1. 현재 KTX·SRT를 포함한 고속철도 승차권 **예매를 운영하는 주체와 창구**가 어떻게 되는지,
>    최근 운영 체계에 변동이 있었다면 그 내용을 안내받을 수 있는지 궁금합니다.
> 2. 열차별 **잔여좌석 조회**가 가능한 공식 API 또는 데이터 제공 방식이 있는지,
>    있다면 이용 신청 방법과 자격 요건을 알고 싶습니다.
> 3. **승차권 예약·발권 연동**(제휴·판매대행 등 형태 불문)이 가능한 경로가 있는지,
>    있다면 문의·접수 창구를 안내받고 싶습니다.
> 4. 위 2·3이 제공되는 경우 인증 방식, 호출 제한, 테스트 환경 제공 여부.
> 5. 해당 사항의 담당 부서가 다르다면, 어느 창구로 문의해야 하는지 안내 부탁드립니다.
>
> 저희는 탐지 회피나 접근 제한 우회를 전제한 개발은 계획하고 있지 않으며,
> 공식적으로 허용되는 범위 안에서만 진행하려 합니다.

### 9-2. 공공데이터 제공 항목 확인

> 제목: 열차 정보 오픈API의 제공 항목 및 대체서비스 확인 요청
>
> 1. 국토교통부(TAGO) 열차정보(데이터셋 15098552)의 **응답 항목 전체 목록**을 확인할 수 있는
>    문서를 안내받고 싶습니다. 특히 **좌석 관련 항목의 포함 여부**를 확인하고자 합니다.
> 2. 해당 오픈API의 호출 중지 또는 대체서비스 전환이 있었다면, 현재 유효한 서비스명과
>    제공 항목을 안내 부탁드립니다.
> 3. 열차 잔여좌석 정보를 제공하는 다른 공공데이터 서비스가 있는지 궁금합니다.
