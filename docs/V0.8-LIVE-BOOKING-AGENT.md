# v0.8 — 실제 좌석 조회·예약 실증 (Local Automation Agent)

이 문서는 RailFlow가 **실제 공식 예매 화면**에서 좌석 상태를 읽고, 사용자가
승인한 경우에만 **결제 직전까지** 예약을 진행하는 기능의 설계와 한계를
기록한다. 시뮬레이터(`/demo`, `/demo/booking-automation`)와는 완전히 별개의
코드 경로다.

---

## 1. 지금 무엇이 되고 무엇이 안 되는가

| 항목 | 상태 |
|---|---|

| LIVE_RESERVATION_ARMED (실제 예약) | 구현 완료, **실제 예약 실증 미완료** |
| 중복 방지·잠금·펜싱 토큰·결과 재확인 | 구현 완료, 자동 테스트 통과 |

| 로컬 화면(웹 UI)과 Agent 연결 | 같은 출처로 재구성 완료 ([V0.8-LOCAL-CONNECTION.md](./V0.8-LOCAL-CONNECTION.md)) |
| 사용자의 JSON 편집 | **제거됨.** 프로필은 Agent가 검증하고 서명한다 |

**이 단계에서 실제 사이트 접속·실제 좌석 읽기·실제 예약은 한 번도 하지
않았다.** 이유는 §2에 있다.

## 2. 왜 이 저장소를 만든 환경에서는 실제 사이트를 열 수 없었나

RailFlow의 코드를 작성한 개발 환경은 외부 통신이 정책으로 통제된다.
공식 예매 관련 호스트로 나가는 연결은 모두 프록시 단계에서 거부됐다.

```
etk.srail.kr:443        CONNECT -> 403 (policy denial)
etk.srail.co.kr:443     CONNECT -> 403
www.srail.or.kr:443     CONNECT -> 403
www.letskorail.com:443  CONNECT -> 403
www.korail.com:443      CONNECT -> 403
```

이 통제를 프록시·우회 경로로 넘지 않았다. 따라서 **실제 DOM을 보지 못했고,
그래서 어떤 선택자도 어떤 화면 문구도 코드에 쓰지 않았다.**

지침이 요구한 "실제 DOM을 확인해 선택자를 작성한다 / 임의의 selector를
추측하지 않는다"를 지키는 방법은 하나뿐이었다: **화면을 볼 수 있는 곳에서
화면을 읽게 만드는 것.** 그게 `capture` 명령이다(§5).

### 대상 사업자 확정 근거와 그 한계

- 사용자가 실증하려는 구간: **동탄 → 울산(통도사)**
- 공개 자료에서 확인한 것: SRT(SR 운영) 경부선 정차역에 동탄과
  울산(통도사)이 있고, 공식 예매 화면은 `etk.srail.kr` 이다.
- **확인하지 못한 것**: 실제 공식 화면 자체. 위 내용은 공개 페이지 검색
  결과이지 공식 화면을 직접 본 것이 아니다.

그래서 대상 호스트조차 코드에 하드코딩하지 않았다. Provider는 프로필에
적힌 호스트만 열며, 그 프로필은 사용자의 PC에서 실제로 접속한 주소로
채워진다. 프로필의 호스트와 다른 주소로는 이동 자체를 거부한다
(`HOST_NOT_ALLOWED`).

## 3. 이번 작업에 적용한 프로젝트 내부 정책 범위

`CLAUDE.md` 의 "공식·승인된 연동 방식 확인 전 구현 금지" 조항과 이번
작업의 관계를 분명히 해 둔다. 이번에 **구현 범위로 정한 것**은 다음이다.

- 사용자가 소유한 계정
- 사용자가 직접 시작한 작업
- 화면이 보이는(headed) 브라우저
- 사용자의 수동 로그인
- 공개된 공식 예매 UI의 일반적인 조회·예약 흐름
- 결제 이전 단계까지만 자동화
- 차단·추가 인증 발생 시 즉시 중단
- 인증정보와 세션을 서버로 전송하지 않음

> **이것은 운영자의 승인이나 이용약관상 허용이 확인됐다는 뜻이 아니다.**
> 프로젝트 내부의 구현 범위를 정한 것이며, 외부 서비스의 이용 조건과는
> 별개다. 외부 이용 조건의 충족 여부는 이 문서로 판단할 수 없고, 지금도
> 확인되지 않았다.

### 구현하지 않은 것 (설계상 제외)

CAPTCHA 해결·우회, 대기열 우회, 봇 탐지 회피, User-Agent·IP·계정·세션
로테이션, 프록시를 통한 차단 회피, 탐지 회피용 요청 간격 무작위화,
비공개 API 추측·복제, 앱 트래픽 가로채기, 차단 응답을 성공으로 위장,
결제 자동화, 카드정보·비밀번호·OTP 저장.

이 목록은 문서상의 약속이 아니라 코드로 막혀 있다.
`agent/src/providers/provider-contract.mjs` 는 Provider에 위 기능에
해당하는 이름(`solveCaptcha`, `bypassQueue`, `rotateProxy`, `exportCookies`,
`autoPay` 등)이 하나라도 있으면 **로드 자체를 거부**한다.

## 4. 실행 구조

Vercel 함수 안에서는 Playwright 브라우저와 사용자 로그인 세션을 유지할 수
없다. 그래서 실제 자동화는 전부 사용자의 PC에서 돈다.

```
[ RailFlow Web UI ]                    [ 사용자의 Windows PC ]
 조건 입력 / 후보 선택                   railflow-agent (Node.js)
 감시 시작·중단                            ├─ 화면이 보이는 Chromium
 상태·이력 표시            <── HTTP ──>    ├─ 사용자가 직접 로그인
 예약 성공·결제기한 표시   127.0.0.1:4319  ├─ 좌석 상태 읽기
                                           ├─ (승인 시) 예약 버튼 클릭
                                           └─ 예약내역 재확인
```

- 웹 UI는 `127.0.0.1` 의 Agent와만 통신한다. **서버(Vercel)는 사용자의
  PC에 접근하지 않으며, 접근을 시도하지도 않는다.**
- Agent를 실행하면 콘솔에 6자리 **연결 코드**가 찍힌다. 그 코드를 웹 화면에
  입력해야 명령이 통한다. 브라우저에서 열린 아무 페이지나 로컬 Agent에
  예약을 시키지 못하게 하는 장치다. 코드는 실행할 때마다 새로 만들어지고
  파일로 저장되지 않는다.

### Provider 인터페이스

`agent/src/providers/provider-contract.mjs` 가 정의하고 검사한다.

```
openBookingSite()      화면이 보이는 브라우저로 조회 화면을 연다
waitForManualLogin()   사용자가 직접 로그인할 때까지 기다린다
searchTrain()          조건을 넣고 후보 열차 행을 특정한다
readSeatAvailability() 좌석 상태를 읽는다
requestReservation()   (승인 시) 예약 버튼을 한 번 누른다
verifyReservation()    예약내역에서 예약 존재를 확인한다
readPaymentDeadline()  결제기한을 화면에서 읽는다
stop()                 브라우저를 닫는다
```

실제 Provider의 이름은 반드시 `live:` 로 시작하고 대상 사업자를 포함해야
한다(`live:SR-SRT@<host>`). 계약 검사가 이를 강제하므로 Mock Provider와
이름이나 모드로 섞일 수 없다.

## 4-A. 2차 라운드에서 바뀐 것

초판(커밋 `73907df`)에서 두 가지를 고쳤다.

### (1) https 배포본 → localhost 호출 구조를 버렸다

배포본 페이지가 `http://127.0.0.1` 을 직접 부르는 구조는 실제 브라우저에서
막힌다(Mixed Content / CORS / Private Network Access). 브라우저 보안 설정을
낮추라고 안내하는 것은 선택지가 아니므로, **Agent가 자기 화면을 직접
제공**하도록 바꿨다. 사용자는 `2-RailFlow실행.cmd` 하나만 누르면 되고,
Agent가 브라우저로 `http://127.0.0.1:4319/` 를 연다.

자세한 분석과 실제 브라우저 확인 결과: [V0.8-LOCAL-CONNECTION.md](./V0.8-LOCAL-CONNECTION.md)

### (2) 사용자가 JSON을 편집하던 것을 없앴다

초판은 사용자가 프로필 JSON을 열어 `"verified": true` 로 바꿔야 했다.
그러면 `verified` 가 "Agent가 검증했다"가 아니라 "누군가 true 라고 적었다"를
뜻하게 된다.

이제는:

- 사용자가 **공식 화면 위에서 요소를 클릭**해 알려준다(오버레이 마법사).
- Agent가 같은 화면을 다시 읽어 **자동 검증**한다.
- 전부 통과했을 때만 **서명**이 붙는다(이 PC에만 있는 키로 HMAC).
- 프로필 내용을 한 글자라도 고치면 서명이 깨져 `PROFILE_TAMPERED` 가 된다.
- **손으로 켤 수 있는 스위치가 존재하지 않는다.**

또 화면 구조 **지문(fingerprint)** 을 프로필에 넣고, 좌석을 읽을 때마다
현재 화면의 지문과 비교한다. 사이트가 개편되면 엉뚱한 칸을 읽는 대신
`PROFILE_FINGERPRINT_MISMATCH` 로 멈춘다.

### (3) 대상 사업자를 파일 이름으로 먼저 정하지 않는다

초판은 `sr-srt.profile.json` 처럼 이름을 먼저 정해 두고 거기에 화면을
맞추는 모양이었다. 이제 프로필 파일 이름은 **사용자가 실제로 연 화면의
호스트**에서 만들어지고, Provider 이름도 프로필의 사업자·호스트에서 온다
(`live:<사업자>@<호스트>`). 저장소의 어떤 파일 이름에도 사업자명이
들어가지 않는다(`scripts/verify-live-agent.cjs` 가 검사한다).

## 5. 사이트 프로필 — "추측하지 않았다"를 구조로 강제하는 장치

Provider는 선택자를 하드코딩하지 않는다. 대신:

1. **구조는 의미로 찾는다.** 결과 표는 `role="row"` / `<tr>` 로 읽고, 열
   위치를 가정하지 않는다. 행 안의 값은 내용으로 식별한다(열차번호처럼
   보이는 것, 시각처럼 보이는 것).
2. **화면 문구는 프로필에서 읽는다.** "매진", "예약하기" 같은 사이트별
   어휘는 코드에 없다. 프로필 파일에 있다.
3. **프로필은 실제 화면에서만 만들어진다.** 로컬 화면의 화면 연결
   마법사가 사용자의 PC에서 공식 화면을 열고, 사용자가 클릭한 자리의
   의미 구조만 기록한다.
4. **검증·서명 전에는 아무 것도 실행되지 않는다.** 서명이 없거나 내용이
   바뀌었으면 `PROVIDER_PROFILE_REQUIRED` / `PROFILE_TAMPERED` 로 거부한다.

기록하는 것: 방문한 주소, 행 기준 상대 위치와 칸 번호, 폼 라벨, 짧은 상태
문구, 화면 구조 지문.
기록하지 않는 것: DOM/HTML 원문, 쿠키, 세션, 토큰, 이름, 회원번호,
전화번호, 이메일, 예약번호, 결제정보.

## 6. 좌석 상태 정규화

화면에 실제로 표시된 내용만 아래로 정규화한다.

`AVAILABLE_STANDARD` · `AVAILABLE_FIRST` · `AVAILABLE_ANY` · `SOLD_OUT` ·
`WAITLIST_AVAILABLE` · `AUTH_REQUIRED` ·
`ADDITIONAL_VERIFICATION_REQUIRED` · `QUEUE_OR_ACCESS_RESTRICTED` ·
`PROVIDER_CHANGED` · `UNKNOWN`

규칙:

- **좌석 수는 화면에 없으면 추정하지 않는다.** `AVAILABLE_*` 는 "예약 가능한
  자리가 표시됐다"는 뜻이지 몇 석인지가 아니다.
- **조회 실패·선택자 실패·로딩 중을 매진으로 처리하지 않는다.** 그런 경우는
  `UNKNOWN` 이거나 `PROVIDER_CHANGED` 다. 자동 테스트로 고정돼 있다.
- 각 상태에는 화면에서 읽은 **원본 문구**가 함께 보존된다(개인정보 마스킹 +
  120자 제한).

## 7. 반복 조회 정책

- 실제 사이트용 주기는 **`livePollingIntervalSeconds`** 라는 별도 이름을
  쓴다. 시뮬레이터의 1~5초 옵션은 여기 연결되지 않는다.
- 기본 **60초**, 하한 **30초**. 설정으로도 하한 아래로 내려갈 수 없다
  (`config.mjs` 와 `runner.mjs` 두 곳에서 강제).
- 주기는 **고정**이다. 탐지 회피 목적의 무작위화는 하지 않는다.
- 후보가 여럿이어도 **한 브라우저 세션에서 순차** 처리한다.
- 사용자당 동시에 실행되는 실제 작업은 **하나**(파일 잠금으로 강제).
- 네트워크 장애는 30·60·120·240초 백오프 후 중단.
- **로그인 만료 시 자동 재로그인을 시도하지 않는다.**
- 공개된 요청 제한을 확인한 경우 그 범위를 따른다. 현재 그 값을 확인하지
  못했으므로 위의 보수적 기본값을 쓴다.

## 8. 예약 안전장치

### 2단계 활성화

1. **LIVE_READ_ONLY** — 실제 검색·실제 좌석 읽기·화면 표시까지만. 좌석을
   찾아도 예약 버튼을 누르지 않고 승인 대기 상태로 멈춘다. 상태 기계가
   읽기 전용 모드에서는 `RESERVING` 으로 가는 전이 자체를 갖고 있지 않다.
2. **LIVE_RESERVATION_ARMED** — 사용자가 화면에서 날짜·구간·후보 열차번호·
   인원·좌석등급을 다시 확인하고 승인해야 열린다. 승인 요청에는 **화면이
   보여준 조건을 그대로 되돌려 보내고**, Agent가 실행 중인 작업과 대조한다.
   하나라도 다르면 예약을 시작하지 않는다.

### 중복 예약 방지

- 동일 사용자·날짜·구간·인원에 활성 작업 하나만(후보 열차는 키에 넣지
  않는다 — 같은 구간을 여러 열차로 동시에 노리는 것이 곧 중복 위험이므로).
- 예약 요청 **직전에 좌석 상태를 다시 확인**한다.
- 예약 요청 **직전에 공식 예약내역에서 기존 예약을 먼저 확인**한다. 있으면
  예약하지 않고 `RECONCILIATION_REQUIRED` 로 중단한다.
- 예약 클릭은 **정확히 한 번**. 결과가 불명확해도 재클릭하지 않는다.
- 예약 확인 또는 기존 예약 발견 시 **나머지 후보 감시를 즉시 중단**한다.
- 파일 잠금 + **펜싱 토큰**: 되돌릴 수 없는 클릭 직전에 자기 토큰이 아직
  최신인지 확인한다. 아니면 클릭하지 않고 중단한다.

### 예약 성공 판정

**버튼을 눌렀다는 사실만으로 성공으로 처리하지 않는다.** 예약내역을 다시
조회해 열차번호·시각·구간이 일치하는 예약을 찾았을 때만 성공이다. 찾지
못하면 `RESULT_UNCERTAIN_USER_CHECK_REQUIRED` 로, 사용자가 직접 확인하도록
남긴다.

---

## 9. 결제 처리

결제는 자동화하지 않는다. 예약 성공 후 표시하는 것:

열차 / 날짜·출발시각 / 구간 / 인원·좌석등급 / 예약번호 / **실제 결제기한** /
"사용자가 공식 예매 서비스에서 직접 결제해야 합니다".

**결제기한은 화면에서 읽은 값만 쓴다.** 읽지 못하면 "화면에서 확인하지
못했습니다"라고 표시하고 추정값을 만들지 않는다. 시뮬레이터의 10분
기한은 실제 값으로 쓰이지 않는다.

예상하지 못한 결제 화면이 뜨면 `UNEXPECTED_PAYMENT_SCREEN` 으로 즉시 중단한다.

---

## 10. 사용자 중단과 오류 처리

- 중단을 누르면 새로운 조회와 클릭을 멈춘다. 조회 주기가 끝나기를 기다리지
  않고 즉시 반응한다.
- **이미 예약 요청을 누른 뒤라면** 단순히 "취소됨"으로 바꾸지 않는다.
  예약내역을 확인해 다음 중 하나로 정리한다: 예약 없음 / 예약 성공 /
  결과 불명확 / 사용자 확인 필요.
- 실제 승차권 예약을 자동으로 **취소하는 기능은 이번 범위에 없다.**
- 브라우저를 닫거나 PC가 절전에 들어가면 작업이 멈춘다. UI에 그렇게
  표시한다. **"화면을 꺼도 계속 작동하는 서버 자동예약"이 아니다.**

## 11. 남은 일

1. 사용자의 Windows PC에서 화면 연결 마법사로 사이트 프로필 완성
2. **LIVE_READ_ONLY 로 실제 좌석 상태 읽기 검증** (동탄 → 울산(통도사))
3. 로그인 만료·화면 변경·매진 중단 동작을 실제 화면에서 확인
4. 읽기 전용 결과를 사용자에게 제시하고 승인받은 뒤 실제 예약 1건 실증
5. 예약 완료 화면과 예약내역 교차 확인, 결제기한 추출 확인
6. 공개된 요청 제한을 확인하고 `livePollingIntervalSeconds` 기본값 재검토
7. 외부 서비스 이용 조건 충족 여부 확인 (이 문서로는 판단할 수 없음)
