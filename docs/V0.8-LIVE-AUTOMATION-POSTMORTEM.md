# v0.8 실사이트 브라우저 자동화 — 중단 기록 (Postmortem)

2026-09. v0.8에서 만든 Local Automation Agent의 **실사이트 경로를 영구
중단**했다. 이 문서는 무슨 일이 있었고, 왜 되살리지 않기로 했으며, 무엇을
남겼는지 기록한다.

---

## 1. 무슨 일이 있었나

| | |
|---|---|
| 대상 | 공식 예매 화면 (`etk.srail.kr`) |
| 방식 | 사용자 PC에서 화면이 보이는 Chromium을 Playwright로 조작, 사용자가 직접 로그인, 좌석 상태 읽기 전용 |
| 결과 | 운영자가 **자동화된 요청으로 판정**해 해당 IP의 접속을 일시 제한 |
| 발생 시점 | v0.8 Local Agent로 실제 접속을 시도한 시점 |

이 시점까지 RailFlow가 수행한 것은 **읽기 전용 조회**였다. 예약 버튼을
누르지 않았고(코드 수준에서 불가능했다), 결제도 하지 않았다.

**그럼에도 제한됐다는 것이 핵심이다.** 조회만 하면 괜찮을 것이라는 전제가
틀렸다.

---

## 2. 실패 원인

기술적 결함이 아니다. 설계 전제가 틀렸다.

1. **운영자 관점에서 "읽기 전용"은 구분되지 않는다.** 브라우저 자동화는
   조회든 예약이든 같은 자동화 트래픽이다. 우리가 내부적으로 예약을 막아
   둔 것은 운영자가 볼 수 있는 정보가 아니다.
2. **주기·빈도를 낮춰도 해결되지 않는다.** 60초 고정 주기에 하한 30초를
   두었지만 판정을 피하지 못했다. 빈도가 유일한 판정 기준이 아니라는 뜻이다.
3. **허용 여부를 확인하지 않은 채 구현이 앞섰다.** v0.8 문서에도 "외부
   서비스의 이용 조건 충족 여부는 확인되지 않았다"고 적어 두었지만, 그
   상태에서 실제 접속을 시도한 것 자체가 순서가 뒤바뀐 것이었다.

---

## 3. 중단 결정

**되살리지 않는다.** 되살리는 방법이 없어서가 아니라, 되살리는 방법이 전부
이 프로젝트가 하지 않기로 한 일이기 때문이다.

### 하지 않기로 한 것 (재시도 금지 범위)

- 자동화 탐지 회피
- 브라우저 지문(fingerprint) 위장
- User-Agent 위조
- 프록시·VPN·IP 순환
- 계정·세션 순환
- CAPTCHA·대기열 우회
- 요청 간격 무작위화로 탐지 회피
- 헤드리스 숨김, `navigator.webdriver` 조작 등 자동화 흔적 제거
- 접속 제한 응답을 성공이나 일시 오류로 위장

위 목록은 문서상의 약속이 아니라 코드로 막혀 있다
(`agent/src/providers/provider-contract.mjs`, `scripts/verify-live-agent.cjs`).

### 되살릴 수 있는 조건

**허용된 연동 경로를 먼저 확보하는 것.** 공개·승인된 API나 제휴·판매대행
경로가 확인되면, 브라우저 자동화가 아니라 그 경로로 새로 설계한다.
같은 코드를 조건부로 되살리는 일은 없다.

---

## 4. 무엇을 막았나

`agent/src/deprecation.mjs` 하나가 상태를 정의한다. 값이 하나뿐이다.

```
LIVE_AUTOMATION_STATUS = "DEPRECATED_BLOCKED"
```

| 막힌 것 | 어디서 |
|---|---|
| 공식 예매 화면 열기 | `live-booking-provider.mjs` `openBookingSite()` 진입 즉시 |
| 화면 연결(프로필 캡처) | `capture.mjs` `open()` 진입 즉시 |
| 실사이트로 나가던 모든 로컬 API 라우트 (11개) | `controller.mjs` 라우트 진입 즉시 |
| 로컬 화면의 시작 버튼 | `console-page.mjs` — 비활성화 + 차단 안내 표시 |

**환경변수로 되살릴 수 없다.** `deprecation.mjs` 는 `process.env` 를 읽지
않는다(테스트로 고정). 켜는 값이 존재하지 않는다.

**이미 설치된 Agent도 업데이트되면 즉시 멈춘다.** 차단이 설정이 아니라
코드 경로에 있기 때문이다. `railflow-agent doctor` 와 실행 배너가
`DEPRECATED_BLOCKED` 를 표시한다.

또 실사이트로 나가던 구현(`#captureStart`, `#probeStart`)은 **삭제**했다.
라우트만 막고 구현을 남기면 "설정 한 줄로 되살릴 수 있다"는 신호가 되기
때문이다.

## 5. 남겨둔 것

지운 것과 남긴 것을 구분한다.

### 남긴 것 (계속 쓸모가 있고, 외부로 요청을 보내지 않는다)

| 자산 | 왜 남기나 |
|---|---|
| `lib/automation/**` Mock 예매 사이트와 시뮬레이터 | RailFlow 자체 Mock만 대상으로 한다. 자동화 로직의 회귀 테스트로 계속 쓴다 |
| `tests/e2e/mock-browser-provider.contract.spec.ts` | 위 Mock 대상 계약 테스트 |
| `tests/e2e/agent-dom-resolver.spec.ts` | DOM 해석기 단위 테스트(표 형태 픽스처 대상) |
| `agent/src/redact.mjs` + 테스트 | 개인정보 마스킹. 어떤 Provider를 쓰든 필요하다 |
| `agent/src/lock.mjs` + 테스트 | 분산 락·펜싱 토큰. 서버형 구조에서 같은 패턴을 쓴다 |
| `agent/src/machine.mjs`, `match.mjs` + 테스트 | 상태 전이·열차 대조 규칙. 경로가 바뀌어도 규칙은 유효하다 |
| `agent/src/profile-signing.mjs` + 테스트 | 검증 결과를 손으로 못 켜게 하는 장치 |
| 로컬 화면(`console-page.mjs`) | 차단 안내와 진단 요약을 보여주는 용도로 남는다 |

### 지운 것

- `#captureStart`, `#probeStart` 구현 (컨트롤러)
- CLI의 `playwright` 로드 요구 (이제 설치돼 있지 않아도 Agent가 동작한다)

### 저장소에 넣지 않은 것

**차단 화면 캡처, Request ID, Ray ID, IP 주소, 계정 식별자를 저장소에 넣지
않았다.** 사용자를 식별할 수 있는 값이기 때문이다. 테스트가 이를 검사한다
(`tests/agent/deprecation.test.mjs`).

---

## 6. 다음 단계와의 관계

v0.9는 이 경로를 고치는 작업이 아니다. **다른 구조로 다시 만드는 작업**이다.

- 서버형 취소표 감시 → 좌석 확보 → **사용자가 공식 앱에서 직접 결제**
- 실제 Provider는 **허용된 연동 경로가 확인된 경우에만** 활성화
- 확인되지 않으면 Stub 상태로 `PROVIDER_UNAVAILABLE` 을 정직하게 표시
