# RailFlow v0.3 작업·검증 기록

## 배포 상태

작업 버전은 v0.3. 현재 공개 주소의 v0.2는 교체하지 않았다. 사용자가 요구한 새 키로 실제 조회 및 최종 화면 검증 조건을 충족한 뒤 배포한다.

공개 주소: https://railflow.dhmailing0310.chatgpt.site

## 화면 원인·조치

날짜/시간 입력의 내재 폭과 2열 카드, 긴 역 이름과 버튼의 단일 행 배치가 좁은 화면에서 충돌할 수 있었다. 입력 width/max-width/min-width를 명시하고 480px 미만에서는 날짜/시간을 세로 배치, 640px 미만에서는 역 선택을 세로 배치했다. 결과 카드와 헤더 정보는 필요한 위치에서 줄바꿈한다. 기존 색상/디자인을 유지했다. 내용을 감추는 overflow 처리는 해결책으로 사용하지 않았다.

## 검증 결과

- TypeScript, ESLint, 프로덕션 빌드 통과(최종 저장 전 재실행).
- Chrome 브라우저의 같은 출처 iframe을 사용한 폭 검사: 320/375/768/820/1024/1180/1440px에서 문서 scrollWidth가 clientWidth를 초과하지 않았다. 작은 폭은 브라우저 스크롤바 15px를 제외한 실제 내부 폭으로도 통과했다.
- 데모 3개 결과 카드와 긴 역 이름 울산(통도사) 표시 확인. 320px 설정 화면도 가로 넘침 없음.
- 역 선택창 클릭으로 목록 열림, 부분 검색, 마우스 선택, 방향키+Enter 선택 확인.
- 날짜만 변경한 뒤 09:30 유지, 초기화 후 00:00 확인. 첫 로딩 00:00 확인.
- 인증키 미설정 상태에서 사용자 안내 및 검색 비활성 상태 확인.
- 브라우저 콘솔에서 관찰된 오류는 검증 브라우저 확장 프로그램의 메타데이터 전송 오류였다. 앱 전체 세션에 오류가 전혀 없다는 보증으로 간주하지 않는다.
- iPad Safari 실기기/실제 터치 검증은 미실행. Chrome의 태블릿 폭 검증과 구별해야 한다.

## 모의 API 검증

테스트용 합성 코드와 가짜 키만 사용하며 인터넷 요청은 하지 않는다. 실제 인증 성공 증거가 아니다.

- 6개 역 목록 동시 2회 조회 → 고유 도시 4건의 외부 요청으로 병합.
- 목록 캐시가 따뜻한 상태에서 동일 검색 동시 2회 → 시간표 요청 1건.
- 동일 조건 재조회 → 시간표 요청 0건.
- 조건 키: 모드·출발 코드·도착 코드·날짜·시간. 운임은 성인 1인 기준이므로 인원은 캐시 구분에서 제외.
- 캐시 60초, 최대 200개, 성공 응답만 저장. 도시/역 목록은 24시간. 메모리 캐시는 Worker 인스턴스마다 분리되며 영속/전역 캐시가 아니다.
- 모의 30ms 외부 지연 기준 측정: 최초 35ms, 캐시 1ms. 실제 TAGO 응답시간 및 v0.2 대비 속도 개선률로 인용하면 안 된다.
- 코드·날짜 전달, 시간 필터, 운임 매핑, 동일 역/잘못된 날짜 차단, 이름-코드 불일치 차단 확인.
- 인증/429/형식 오류/timeout/네트워크 오류/결과 없음 구별. 오류 캐시 안 됨.
- timeout 10초, 네트워크 TypeError에만 1회 재시도. 인증·429·timeout 재시도 없음. 클라이언트 전체 검색 제한 25초.
- 브라우저 검색은 조건 변경/초기화/새 요청 시 AbortController로 취소. 서버에서 이미 공유 중인 외부 조회는 다른 사용자를 위해 완료될 수 있다.

## 성능의 남은 검증

기존 v0.2 페이지 JS 청크는 198,982 bytes였다. 검색형 Combobox 도입 후 추가 코드가 필요하며, 설정 분리와 인원 선택 간소화를 적용한 중간 빌드의 페이지 청크는 214,618 bytes였다. 분리된 공유 청크도 있어 이 단일 청크만으로 전체 초기 전송량을 비교하면 안 된다. 초기 JS 감소나 실제 초기 렌더링 개선은 아직 입증하지 못했다. 서비스 워커의 첫 HTML 중복 요청은 제거했다.

실제 TAGO 대기시간, 수정 전후 동일 환경의 렌더링 시간, 브라우저에서 지연 응답 중 연속 검색 취소 측정은 후속 검증 대상이다.

## 보안·재개 조건

- 노출된 키는 이번 작업에서 사용하지 않았다. Sites의 다음 배포용 DATA_GO_KR_SERVICE_KEY를 제거했다(환경 설정 revision 2).
- 이 삭제는 현재 실행 중인 v0.2의 키를 즉시 무효화하지 않는다. 공공데이터포털에서 이전 키를 폐기/재발급해야 한다.
- 새 키는 서버 Secret DATA_GO_KR_SERVICE_KEY에만 등록한다. 채팅·코드·README·로그에 키 값을 쓰지 않는다.
- 새 키 등록 후 실제 동탄→울산 및 서울→부산 조회와 공식 코드 목록 검증, Safari 검증을 마친 뒤 기존 주소에 배포한다.
- 되돌릴 기준은 기존 저장 버전 2. 롤백하더라도 폐기 키는 복원하지 않고 새 Secret을 유지해야 한다.
