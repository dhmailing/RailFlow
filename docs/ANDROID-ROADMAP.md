# RailFlow Android 앱 로드맵

이 문서는 계획이며, 이번 PR은 Android 앱 코드를 포함하지 않는다. 서버(RailFlow v0.4 예약 작업 기반)가 먼저 안정화된 뒤 착수한다.

## 1. 최종 목표

Google Play에 배포되는 Android 앱에서 사용자가 출발역·도착역·날짜·시간·열차 종류·인원을 입력하고, 검색 결과에서 후보 열차를 선택하고, 일반실/특실 우선순위와 희망 시간 범위를 지정해 자동예약 작업을 등록한다. 앱을 종료하거나 화면을 꺼도 서버가 작업을 유지하며, 승인된 철도 Provider를 통해 좌석을 확보하면 FCM·이메일·텔레그램으로 알린다. 결제는 사용자가 결제기한 안에 코레일+ 등 공식 채널에서 직접 한다. **RailFlow는 v1.0에서 카드번호·카드 비밀번호를 저장하거나 자동 카드결제를 수행하지 않는다.**

## 2. 기술 스택

| 항목 | 결정 |
| --- | --- |
| 언어/UI | Kotlin + Jetpack Compose |
| 최소/타깃 API | API 36 이상 |
| 알림 | Firebase Cloud Messaging(FCM) |
| 딥링크 | Android App Links(공식 도메인 검증, 커스텀 스킴 단독 사용 금지) |
| 백그라운드 지속성 | 클라이언트가 아니라 **서버**(v0.4 Queue/Worker)가 작업을 유지한다. 앱은 상태를 조회·수신만 한다. |
| 자동화 방식 | 서버 API 호출만 사용한다. **AccessibilityService, 화면좌표 클릭, OCR 기반 자동조작은 사용하지 않는다.** |

## 3. 서버 연동 범위

앱은 `docs/V0.4-ARCHITECTURE.md`의 API(`/api/reservations/*`)를 그대로 호출하는 클라이언트다. v0.4 시점에는 사용자 인증이 없으므로, 실제 계정 시스템(로그인·기기 바인딩)이 이 API 앞단에 먼저 붙어야 Android 앱이 개인화된 작업을 안전하게 만들 수 있다. 이는 이번 PR 범위 밖이며, 별도 PR에서 다룬다.

## 4. 개인정보·계정

- 앱 내 개인정보처리방침 화면과 계정 삭제 경로를 제공한다(설정 → 계정 삭제).
- 앱을 삭제해도 계정을 지울 수 있도록 **외부 웹 계정삭제 페이지**를 별도로 둔다(Play 정책상 앱 삭제만으로 계정 삭제를 대체할 수 없음).
- 계정 삭제 시 사용자 데이터·예약조건·알림 토큰(FCM)·연동정보를 서버에서 삭제하는 흐름을 함께 설계한다(§5 보안 기준과 연결).
- 실제 철도 계정 비밀번호나 세션은 앱·서버 어디에도 저장하지 않는다.

## 5. 배포

- AAB(Android App Bundle) + Play App Signing.
- 내부 테스트 → 비공개(폐쇄) 테스트 → 프로덕션 단계적 출시.
- **신규 개인 개발자 계정**으로 등록하는 경우, Play 정책상 프로덕션 공개 전에 **비공개 테스트 12명 이상 · 14일 이상** 요건을 충족해야 한다. 일정에 이 기간을 미리 반영한다.

## 6. 단계별 계획 (초안, 순서는 서버 안정화 상황에 따라 조정)

1. 서버: 사용자 인증(계정) 도입 — v0.4의 `demo-` 스코프를 대체.
2. 서버: 영속 저장소(ADR 0001) 도입, 알림 발송(FCM/이메일/텔레그램) 연동.
3. Android: 검색·후보 선택·자동예약 등록 화면(Compose), 서버 API 연동.
4. Android: FCM 알림 수신 → 결제기한 안내(딥링크로 코레일+ 등 공식 채널 유도, 앱 내 자동결제 없음).
5. Android: 개인정보처리방침·계정삭제(앱 내 + 외부 웹) 완성.
6. 배포 준비: AAB 빌드, Play App Signing 등록, 내부 테스트 → 비공개 테스트(신규 계정이면 12명·14일) → 단계적 프로덕션 출시.

## 7. 범위 밖 — 절대 하지 않는 것

- 코레일/SR 매크로 탐지 우회, 요청/클릭 간격 무작위화, User-Agent·IP·세션·기기정보 로테이션.
- 코레일+ 앱·웹을 AccessibilityService, 화면좌표, OCR, 자동클릭으로 조작.
- 비공개 API·내부 엔드포인트·앱 트래픽의 역공학 또는 복제.
- CAPTCHA, 2단계 인증, 접속제한, 대기열, 봇 방지 기능의 우회.
- 계정 차단·호출 제한 회피를 위한 프록시/다중 IP/다중 계정.
