# RailFlow v0.4 — 코레일 실시간 예약·결제 공식 연동 사전 조사

작성일: 2026-09-19. 실제 인증키, 계정 정보는 포함하지 않는다.

## 이 문서를 읽기 전에 반드시 확인할 것

**코레일과 SR(에스알)은 더 이상 별개 기관이 아니다.** 조사 중 이 사실을 발견해 조사 방향 자체를 바꿨다.

- 공정거래위원회가 코레일·SR 기업결합을 승인했고, 통합 앱 **"코레일+"**가 **2026-08-03** 출시, **2026-09-01**부터 KTX·SRT 통합 운행이 시작됐다(기존 SRT 차량은 "KTX-산천"으로 운용).
- 근거: [대한민국 정책브리핑(korea.kr, 정부 뉴스 포털)](https://www.korea.kr/news/policyNewsView.do?newsId=148969267), [한국경제](https://www.hankyung.com/article/202608019268i), [서울신문](https://www.seoul.co.kr/news/economy/2026/08/02/20260802500015), [코리아데일리](https://www.koreadaily.com/article/20260830225033104), [철도경제신문](https://www.redaily.co.kr/news/articleView.html?idxno=17450) — 확인일 2026-09-19, 검색엔진 스니펫 교차확인.
- **이 세션은 `korail.com`, `srail.or.kr`, `korea.kr`, `data.go.kr`, `law.go.kr`, `data.kric.go.kr` 등 이 조사에 필요한 거의 모든 공식 도메인에 네트워크 정책상 직접 접속하지 못했다.** 아래 모든 내용은 검색엔진이 반환한 스니펫을 근거로 하며, **원문 페이지를 직접 열람하지 못했다.** 각 항목마다 확인 수준을 표시했다. v0.4 실제 착수 전 사용자가 직접 원문을 열람해 재확인해야 한다.
- 조직 통합은 "최대 3년간 한시 조직(통합사업관리 부문)"으로 운영한다는 보도도 있어(dailian.co.kr, 확인일 2026-09-19), 시스템·계약 창구가 완전히 일원화되기까지 과도기가 있을 수 있다.

**결론**: 아래 조사는 "코레일과 SR을 구분"하는 대신, **통합된 단일 기관(코레일)** 기준으로 정리했다. SR 고유의 레거시 정보는 참고용으로만 별도 표시했다.

## 1. 요약 (결론 먼저)

| 항목 | 상태 |
|---|---|
| 실시간 잔여좌석 조회 공식 API(셀프서비스) | **확인되지 않음.** 공공데이터포털·TAGO 계열은 시간표·운임만 제공(§2). 코레일 자체 오픈API는 "승차권 진위확인"만 확인됨(§3) — 잔여좌석이 아님. |
| 좌석 임시확보·예약 API | **확인되지 않음.** |
| 결제·발권·취소·환불 API | **확인되지 않음.** |
| 실제 예약·발권이 되는 외부 연동 사례 | **있음, 단 셀프서비스 아님.** 클룩(Klook) 등 해외 OTA와 "승차권 판매 계약" 체결 방식(§4) — 개별 사업 제휴 계약이지 공개 개발자 포털 신청이 아니다. |
| 개인 개발자가 신청 가능한 경로 | **확인되지 않음.** 지금까지 찾은 모든 잔여좌석/예약 관련 경로는 법인 대 법인 계약으로 보인다. |

## 2. 이미 사용 중인 TAGO(공공데이터포털) 계열 — 한계 재확인

- RailFlow v0.3이 쓰는 "국토교통부_(TAGO)_열차정보"(`apis.data.go.kr/1613000/TrainInfo`)는 **운행시간표·운임만 제공**하며 좌석 잔여·예약·결제·발권 기능이 없다. 이는 공식 데이터 항목 설명 자체에 명시돼 있다(RailFlow 코드의 `seatAvailability:false`, `availability:"unknown"` 처리와 일치).
- 출처: https://www.data.go.kr/data/15098552/openapi.do — **확인일 2026-09-19, 직접 열람 못 함(egress 차단), 검색 스니펫 및 기존 세션 조사(2026-09-19 앞선 대화)를 근거로 함.**

## 3. 코레일 자체 오픈API — 확인된 것은 "승차권 진위확인"뿐

- 한국철도공사가 행정안전부와 협업해 **"승차권 진위확인 조회 서비스"**를 공공데이터포털을 통한 Open API로 제공한다. 용도는 **출장비 정산 시스템 연계**(입력한 승차권 번호·승차일자로 실제 발권/취소 여부, 구간, 시간, 열차정보를 조회) — **잔여좌석 조회나 예약이 아니다.**
- 신청 대상: 민간기업은 공공데이터포털 기업회원 가입 후 활용신청, 공공기관은 기존 기관 계정으로 이용.
- 출처: [Open API 매뉴얼 PDF](https://info.korail.com/crosseditor_u/binary/files/000001/OpenAPI_ticket.pdf), [공공데이터포털 공지](https://www.data.go.kr/bbs/ntc/selectNotice.do?originId=NOTICE_0000000003582) — **확인일 2026-09-19, 직접 열람 못 함, 검색 스니펫 근거.**
- 판단: 이 API는 v0.4 목표(잔여좌석·예약·결제·발권)와 무관하다. 참고용으로만 기록한다.

## 4. 실제 예약이 되는 외부 연동 — 클룩(Klook) 사례

- 코레일이 글로벌 여행 플랫폼 **클룩(Klook)과 "승차권 판매 계약"을 체결**, 2026-03부터 외국인 이용객이 클룩 홈페이지·앱에서 KTX·새마을·무궁화 승차권을 **실시간 조회·예매**할 수 있다(15개 언어, 40개 통화, 간편결제 지원). 코레일은 2018년 트립닷컴을 시작으로 위챗페이·알리페이 등으로 해외 결제 연동을 확대해왔다.
- 클룩 측 자료에 따르면 "맞춤형 SaaS 솔루션 또는 API"로 연동한다고 밝히고 있으나, **이는 클룩이라는 특정 대형 OTA와의 개별 사업 계약**이며, 일반에 공개된 셀프서비스 개발자 포털(신청서 작성 → API 키 발급 방식)이 아니다.
- 출처: https://en.fnnews.com/news/202510241029451679 , https://www.korearailroad.kr/news/articleView.html?idxno=74511 , [클룩 파트너십 신청 페이지](https://www.klook.com/ko/partner/)(클룩 측 창구, 코레일 창구 아님) — **확인일 2026-09-19, 직접 열람 못 함, 검색 스니펫 근거.**
- **판단(추정)**: 실시간 잔여좌석·예약·발권을 외부 플랫폼에 제공하는 것은 기술적으로 가능하지만, 코레일이 **개별 사업 제휴 계약**을 통해서만 열어주는 것으로 보인다. RailFlow가 이 경로를 쓰려면 코레일과 직접 사업 제휴를 협의해야 할 가능성이 높다 — **이는 추정이며, 코레일 사업제휴 담당 부서에 직접 문의해 확정해야 한다.**

## 5. 레일포털(KRIC, 철도산업정보센터) — 추가 확인 필요

- `data.kric.go.kr`("레일포털")는 공공·민간 철도 유관기관의 철도 데이터를 통합 제공하는 별도 포털이다(공공데이터포털과 다른 시스템).
- 개인·법인 모두 온라인 회원가입만으로 이용계약이 성립하고 인증키를 발급받는 구조로 확인된다(자격 제한이 거의 없어 보임).
- **그러나 여기에 KTX 잔여좌석 조회나 예약 관련 API가 포함되는지는 검색 스니펫만으로 확인하지 못했다.** 여객열차 운행계획/운행정보 데이터는 언급되나, 이는 §2의 TAGO 계열과 유사한 시간표성 데이터로 보이며 잔여좌석과는 다를 가능성이 높다.
- 출처: https://data.kric.go.kr/rips/serviceInfo/openapi/process.do , https://data.kric.go.kr/rips/serviceInfo/introduce.do , https://openapi.kric.go.kr/rips/M_01_02/intro.do — **확인일 2026-09-19, 직접 열람 못 함(egress 차단).**
- **조치 필요**: 이 포털에 직접 접속해 "개방데이터" 전체 목록에서 잔여좌석/예약 관련 API 존재 여부를 확인해야 한다. 이 세션은 접속이 막혀 있어 사용자가 직접 확인해야 하는 항목이다.

## 7. 비용·보증금·수수료·샌드박스

- 공공데이터포털·레일포털 계열 API는 일반적으로 무료로 알려져 있으나(공공데이터 개방 원칙), 이번 조사에서 TAGO/레일포털의 명시적 요금 조항을 원문으로 확인하지 못했다.
- §4(클룩형 사업 제휴)의 초기비용·보증금·수수료·정산 조건은 **전혀 공개된 자료를 찾지 못했다.** 이런 유형의 B2B 판매 계약은 통상 비공개 협상 사항이며, 코레일에 직접 문의하지 않고는 알 수 없다.
- 샌드박스/테스트 환경: TAGO·레일포털 계열은 발급받은 실제 서비스키로만 호출하는 구조로 보이며(RailFlow가 이미 겪은 것과 동일한 패턴), 별도 샌드박스 존재 여부는 확인하지 못했다. §4 계열의 테스트 환경 제공 여부도 확인하지 못했다.

## 8. 법률·규제 검토 (확인 수준 낮음 — 법률 자문 필요)

**주의: 이 절은 2차 자료(법률사무소 블로그, 핀테크 자문사 자료 등) 기반이며 법제처·금융위원회 원문을 직접 확인하지 못했다. 실제 v0.4 착수 전 반드시 변호사·법무 자문을 받아야 한다.**

- **통신판매업 신고**: 「전자상거래 등에서의 소비자보호에 관한 법률」 제12조 및 시행령 제40조에 따라, 온라인으로 반복적으로 유상 판매를 중개·대행하면 관할 시·군·구에 통신판매업 신고가 필요하다. 간이과세자 또는 직전연도 거래 50회 미만이면 면제될 수 있다는 자료가 있으나, RailFlow가 실제로 "승차권 판매"를 직접 수행하는 구조인지(코레일 위탁판매 vs 단순 안내) 여부에 따라 적용이 달라질 수 있어 개별 확인이 필요하다.
  - 출처: [국가법령정보센터](https://www.law.go.kr/lsInfoP.do?lsId=009318) — **직접 열람 못 함.**
- **전자지급결제대행업(PG) 등록**: 「전자금융거래법」상 제3자를 위해 결제정보를 송수신하거나 대금 정산을 대행·매개하면 금융위원회 등록 대상이 될 수 있다(자본금 등 요건이 거래 규모별로 다르다는 2차 자료 존재). **다만 RailFlow가 직접 PG업을 등록하는 대신 기존 등록된 PG사(예: 토스페이먼츠, 이니시스 등)를 결제 대행으로 이용하는 일반적인 이커머스 구조를 택하면 이 등록 자체가 불필요할 가능성이 높다** — 이는 흔한 실무 패턴이지만 법률 자문으로 확정해야 한다.
  - 출처: 금융위원회 보도설명자료(2차 인용), Lexology, 고위드 등 — **원문 미확인.**
- **개인정보보호**: 승객 성명·연락처·결제정보 등을 다루면 「개인정보보호법」상 처리방침 고지, 목적 외 이용 금지, (제3자 위탁 시) 위탁 계약, 필요 시 개인정보보호위원회 관련 의무가 발생한다. 구체적 조항까지는 확인하지 못했다.
- **여객운송·철도사업법상 승차권 판매대리점 자격**: 「철도사업법」 및 시행규칙에 판매대리점 관련 조항이 있을 것으로 보이나, 이번 조사에서 조문 자체를 확인하지 못했다(law.go.kr 접속 차단).

## 10. 종합 판단과 권장 다음 단계

1. **v0.4 목표(잔여좌석~발권)를 셀프서비스 오픈API로 달성할 공식 경로는 이번 조사에서 찾지 못했다.** 확인된 유일한 실제 사례(클룩)는 대형 OTA와의 개별 사업 계약으로 보인다.
2. 다음으로 확정해야 할 것(이 세션이 직접 할 수 없는 것):
   - 레일포털(data.kric.go.kr) 개방데이터 전체 목록을 직접 열람해 잔여좌석/예약 API 존재 여부 확인
   - 코레일 대표번호(1588-7788) 또는 여객사업본부에 **사업 제휴 신청 절차**를 공식 문의(개인/소규모 서비스도 가능한지, 조건이 무엇인지)
   - 통신판매업·PG·개인정보 처리 요건을 변호사·법무 자문으로 확정
3. 이 모든 것이 확정되기 전까지, RailFlow는 v0.3에서 이미 지키고 있는 원칙(시간표·운임만 제공, `availability:"unknown"`, 좌석 확보·예약·결제·발권을 구현된 것처럼 표시하지 않음)을 v0.4 착수 전까지 계속 유지해야 한다.
