## 1. 좌석 상태 (SeatStatus)

화면에 **실제로 표시된 내용**만 여기로 정규화한다.

| 코드 | 뜻 | 화면 표시 |
|---|---|---|
| `AVAILABLE_STANDARD` | 일반실 예약 가능 표시 | 일반실 예약 가능 |
| `AVAILABLE_FIRST` | 특실 예약 가능 표시 | 특실 예약 가능 |
| `AVAILABLE_ANY` | 등급 구분 없이 예약 가능 표시 | 예약 가능 |
| `SOLD_OUT` | 매진 표시 | 매진 |
| `WAITLIST_AVAILABLE` | 예약대기 가능 표시 | 예약대기 가능 |
| `AUTH_REQUIRED` | 로그인이 필요하다는 표시 | 로그인 필요 |
| `ADDITIONAL_VERIFICATION_REQUIRED` | 추가 본인인증·보안문자 표시 | 추가 인증 필요 |
| `QUEUE_OR_ACCESS_RESTRICTED` | 대기열·접근 제한 표시 | 접근 제한 |
| `PROVIDER_CHANGED` | 직전에 확인한 행/구조를 다시 못 찾음 | 화면 변경 |
| `UNKNOWN` | 읽었으나 어떤 상태인지 판별 불가 | 확인 불가 |

**규칙**

- 좌석 수가 화면에 없으면 잔여 수량을 추정하지 않는다.
- `UNKNOWN` 과 `PROVIDER_CHANGED` 를 **매진으로 처리하지 않는다.**
- `UNKNOWN` 은 예약 조건을 절대 만족하지 않는다(클릭으로 이어지지 않는다).

## 2. 작업 상태 (JobState)

| 코드 | 화면 표시 | 다음에 무엇이 일어나나 |
|---|---|---|
| `IDLE` | 대기 | 시작 대기 |
| `LAUNCHING_BROWSER` | 브라우저 실행 중 | 화면이 보이는 Chromium 실행 |
| `WAITING_MANUAL_LOGIN` | 로그인 대기 | 사용자가 직접 로그인 |
| `CONNECTED` | 실제 사이트 연결됨 | 조회 시작 |
| `SEARCHING_TRAIN` | 열차 확인 중 | 후보 열차 행 특정 |
| `TRAIN_CONFIRMED` | 열차 확인됨 | 좌석 상태 읽기 |
| `WATCHING_SOLD_OUT` | 좌석 없음 · 감시 중 | 고정 주기로 재확인 |
| `SEAT_FOUND` | 좌석 발견 | 모드에 따라 승인 대기 또는 예약 |
| `AWAITING_ARM_CONFIRMATION` | 예약 승인 대기 | **사용자 승인 전까지 사이트를 다시 조회하지 않는다** |
| `RESERVING` | 예약 요청 중 | 예약 버튼 1회 클릭 |
| `VERIFYING_RESERVATION` | 예약 결과 확인 중 | 예약내역 재조회 |
| `RESERVED_PAYMENT_REQUIRED` | 예약 성공 · 결제 필요 | **종료.** 사용자가 직접 결제 |
| `AUTH_REQUIRED` | 로그인 필요 | **종료.** 자동 재로그인 없음 |
| `ADDITIONAL_VERIFICATION_REQUIRED` | 추가 인증 필요 | **종료.** 우회하지 않음 |
| `QUEUE_OR_ACCESS_RESTRICTED` | 접근 제한으로 중단 | **종료.** 우회하지 않음 |
| `PROVIDER_CHANGED` | 화면 변경으로 중단 | **종료.** 잘못된 열차 클릭 방지 |
| `RESULT_UNCERTAIN_USER_CHECK_REQUIRED` | 결과 불명확 · 사용자 확인 필요 | **종료.** 재클릭하지 않음 |
| `RECONCILIATION_REQUIRED` | 기존 예약 확인 필요 | **종료.** 중복 예약 방지 |
| `STOPPED_BY_USER` | 사용자 중단 | **종료** |
| `FAILED` | 실패 | **종료** |

종료 상태에서는 자동으로 어디로도 가지 않는다. 사용자의 명시적인 재시작이
필요하다.

### 모드별 전이 제한

- `LIVE_READ_ONLY` 에서는 `SEAT_FOUND → RESERVING` 전이가 **존재하지 않는다.**
- `LIVE_RESERVATION_ARMED` 에서만 `SEAT_FOUND`/`AWAITING_ARM_CONFIRMATION →
  RESERVING` 이 열린다.
- 중단 상태(로그인 필요·추가 인증·접근 제한·화면 변경·기존 예약·결과
  불명확·실패)는 **활성 상태 어디서든** 도달할 수 있다. 차단은 언제 나타날지
  모르기 때문이다.
- 예약 요청을 누른 뒤(`RESERVING`, `VERIFYING_RESERVATION`)에는 사용자가
  중단을 눌러도 곧바로 `STOPPED_BY_USER` 가 되지 않고 `VERIFYING_RESERVATION`
  으로 간다. 예약이 생겼는지 확인하지 않고 "취소됨"으로 적으면 안 되기 때문.

## 3. 중단 사유 (HaltReason)

| 코드 | 언제 | 대응 |
|---|---|---|
| `USER_STOP` | 사용자가 중단 | — |
| `CAPTCHA_DETECTED` | 보안문자 화면 | 즉시 중단. **해결·우회하지 않음** |
| `QUEUE_DETECTED` | 대기열 화면 | 즉시 중단. **우회하지 않음** |
| `ACCESS_RESTRICTED` | 접근 제한·차단 응답 | 즉시 중단 |
| `ADDITIONAL_VERIFICATION` | 추가 본인인증 요구 | 즉시 중단 |
| `LOGIN_EXPIRED` | 로그인 만료 | 즉시 중단. **자동 재로그인 없음** |
| `UNEXPECTED_PAYMENT_SCREEN` | 예상치 못한 결제 화면 | 즉시 중단 |
| `PROVIDER_PROFILE_REQUIRED` | 사이트 프로필이 없거나 미완성 | 로컬 화면에서 "공식 화면 연결" 진행 |
| `PROFILE_TAMPERED` | 프로필이 검증 이후 변경됨 (손으로 고쳤거나 다른 PC 것) | 다시 연결 |
| `PROFILE_VERIFICATION_STALE` | 검증 규칙 버전이 달라짐 | 다시 연결 |
| `PROFILE_FINGERPRINT_MISMATCH` | 화면 구조가 캡처 당시와 다름 | 중단. 다시 연결 |
| `UNEXPECTED_RESERVATION_SCREEN` | 읽기 전용인데 예약 화면으로 넘어감 | 즉시 중단 |
| `RESERVATION_NOT_ARMED` | 읽기 전용 단계에서 예약이 호출됨 | 수행하지 않음 |
| `PROVIDER_LAYOUT_CHANGED` | 폼·버튼·표를 찾지 못함 | 중단. **좌표 클릭으로 우회하지 않음** |
| `TRAIN_IDENTIFICATION_UNCERTAIN` | 열차 식별 불확실(PARTIAL/AMBIGUOUS) | 중단. **클릭하지 않음** |
| `RESERVATION_RESULT_UNCERTAIN` | 클릭했으나 예약내역에서 미확인 | 중단. **재클릭하지 않음** |
| `EXISTING_RESERVATION_FOUND` | 같은 조건의 기존 예약 발견 | 중단. 중복 예약 방지 |
| `HOST_NOT_ALLOWED` | 프로필이 허용한 호스트 밖 | 이동 자체를 거부 |
| `NETWORK_BACKOFF_EXHAUSTED` | 백오프 상한 초과 | 중단 |
| `LOCK_LOST` | 더 최신 실행이 잠금을 가져감 | 클릭 직전이라도 중단 |

## 4. 열차 식별 결과 (matchCandidateRow)

| 결과 | 뜻 | 동작 |
|---|---|---|
| `MATCHED` | 열차번호·출발시각·출발역·도착역이 모두 맞는 행이 **정확히 하나** | 진행 |
| `NOT_FOUND` | 열차번호가 맞는 행이 없음 | 중단 |
| `PARTIAL` | 열차번호는 맞는데 다른 항목이 다름 | 중단 |
| `AMBIGUOUS` | 모두 맞는 행이 둘 이상 | 중단 |

`MATCHED` 가 아니면 **절대 클릭하지 않는다.**

## 6. 읽기 전용 실증 단계 (ReadOnlyProbe)

`phase` 값은 지금 어느 단계인지를 나타낸다. 지침 §9의 순서를 그대로 따른다.

| phase | 뜻 |
|---|---|
| `OPEN` | 브라우저 실행 |
| `LOGIN` | 사용자의 수동 로그인 대기 |
| `CONNECTED` | 로그인 확인됨 |
| `SINGLE_SEARCH` | 단건 열차 검색 |
| `SINGLE_READ` | 단건 좌석 상태 읽기 (1회차) |
| `RECHECK` | 같은 열차 재조회 (2회차) + 일관성 확인 |
| `POLLING` | 60초 고정 주기 감시 |
| `STOPPED` | 사용자 중단 |

**`RECHECK` 를 통과해야만 `POLLING` 으로 간다.** 캡처 직후 곧바로 반복
감시로 들어가지 않는다.

일관성 확인에서 보는 것: 두 번의 조회가 **같은 열차번호·같은 출발시각**을
읽었는가. 좌석 상태 자체는 비교하지 않는다 — 바뀌는 것이 정상이다.
두 번 모두 상태 문구를 해석하지 못하면(`UNKNOWN`) 매진이 아니라
`PROVIDER_CHANGED` 로 중단한다.

## 7. 프로필 검증 (capture)

프로필은 아래 검사를 **모두** 통과해야 서명되고 사용 가능해진다.
하나라도 실패하면 서명하지 않으며, 사용자가 손으로 켤 수 있는 스위치는
존재하지 않는다.

1. 조회 화면에서 검증
2. 열차 행을 다시 찾음
3. 열차번호 자리에서 열차번호를 읽음
4. 출발시각 자리에서 시각을 읽음
5. 일반실 상태 자리에서 문구를 읽음
6. 상태 문구 분류가 채워짐
7. 조회 폼 항목이 채워짐
8. 예약내역 화면이 기록됨

`verification.verifierVersion` 이 현재 버전과 다르면 프로필은 무효가 된다
(검증 규칙이 바뀌었다는 뜻이므로 다시 만들어야 한다).
