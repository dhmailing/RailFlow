# v0.9 코레일 통합 예약 경로 조사

조사일: 2026-09-28. 목적: **서버형 자동예약을 허용된 경로로 구현할 수
있는가**를 판단하는 것.

각 항목을 다음 등급으로 구분한다.

- **확인됨** — 여러 공개 출처가 일치하고, 이 프로젝트의 판단 근거로 쓸 수 있는 것
- **잠정 정보** — 검색 결과에는 나오지만 공식 원문과 대조하지 못한 것. 수치·기한·
  세부 규칙이 여기 들어간다
- **원문 확인 필요** — 실제 구현·안내 문구에 쓰려면 공식 원문을 반드시 확인해야 하는 것
- **미확인** — 존재 여부 자체를 확인하지 못한 것
- **지원하지 않음** — 공개된 범위에서 제공되지 않는 것으로 확인된 것

**출처는 전부 공개 웹 검색 결과이며, 코레일·SR 공식 페이지 본문은 이 작업
환경의 네트워크 정책 때문에 직접 열지 못했다(§5).** 따라서 검색 결과 요약과
공식 원문 확인을 같은 것으로 취급하지 않는다. 기한·횟수·시행범위처럼 숫자가
들어가는 항목은 원칙적으로 `잠정 정보` 이하다.

## 1. 결론 먼저

**좌석 잔여 조회와 예약 생성을 지원하는 공개·승인 API를 확인하지 못했다.**
따라서 지침 §3에 따라 실제 Provider 구현을 중단하고 Stub 으로 남긴다.

다만 조사 과정에서 **제품 방향을 바꿀 만한 사실 두 가지**를 확인했다.

1. **코레일에 이미 공식 "예약대기" 기능이 있다(확인됨).** 매진 열차에 반환석이
   생기면 대기 신청자에게 배정되는 구조로 안내된다. RailFlow가 하려던 일의
   상당 부분을 운영자가 공식적으로 제공하고 있다. **신청 기한과 배정 상세
   기준은 잠정 정보**이므로 사용자 안내 문구에 쓰기 전에 원문을 확인해야 한다
   (§2-2).
2. **2026년 9월 KTX·SRT 통합 운행이 시작됐다(확인됨).** 코레일 계정으로 통합
   예매가 되는 방향이며, 브라우저 자동화가 SRT 사이트를 따로 다루던 전제가
   바뀌었다. **개시일·적용 열차 등 세부 시행범위는 잠정 정보다**(§2-3).

### 1-1. 이 문서와 무관하게 확정적으로 말할 수 있는 것

아래 다섯 가지는 외부 조사 결과가 아니라 **이 저장소의 코드 상태**이므로
조건 없이 확정이다.

1. **좌석 잔여 조회·예약 생성을 지원하는 공개 API 명세를 확보하지 못했다.**
2. **실제 좌석 조회·예약 Provider는 Stub 이다.** `official-approved` 는 호출되면
   `OFFICIAL_INTEGRATION_REQUIRED` 로 실패한다.
3. **이 작업에서 코레일·SR로 보낸 실제 요청은 0건, 실제 예약은 0건이다.**
4. **Mock Provider는 개발·테스트 전용이다.** 외부로 요청을 보내지 않으며,
   Production 에서는 선택될 수 없다.
5. **Production 기본값은 fail-closed 다.** Provider·저장소·작업 실행이 모두
   기본 비활성이고, 명시적으로 켜야 동작한다.

## 2. 항목별 확인 결과

### 2-1. 코레일 Open API 범위

| 항목 | 상태 | 내용 |
|---|---|---|
| 열차운행정보 API 존재 | **확인됨** | 공공데이터포털에 한국철도공사 열차운행정보(운행계획·운행정보) 제공. 운행일, 열차번호, 출발·도착역 코드/명, 시각 |
| 열차운행정보 API 일일 호출 제한 | **원문 확인 필요** | 안내상 "무료, 일일 제한 없음"으로 검색되지만 포털의 활용신청 화면·운영정책 원문을 대조하지 못했다. **제한이 없다고 가정한 설계를 하지 않는다** |
| 승차권 진위확인 API 존재 | **확인됨** | **예매용이 아니라 사후 검증용**. 좌석 조회·예약에는 쓸 수 없다 |
| 승차권 진위확인 조회 가능 시점·범위 | **잠정 정보** | 검색 결과상 탑승일 2일 후부터, 범위 최대 6개월. 공식 명세 원문은 확인하지 못했다 |
| **좌석 잔여 조회 API** | **지원하지 않음(공개 범위에서)** | 검색된 코레일 Open API 목록에 없음 |
| **예약 생성 API** | **지원하지 않음(공개 범위에서)** | 동일 |
| **예약 조회·취소 API** | **지원하지 않음(공개 범위에서)** | 동일 |

> "지원하지 않음"은 **공개된 Open API 목록에서 확인되지 않았다**는 뜻이다.
> 비공개 내부 API의 존재 여부를 부정하는 것이 아니며, 있더라도 이 프로젝트는
> 추측하거나 복제하지 않는다.

RailFlow가 이미 쓰는 TAGO 열차정보도 같은 범위(시간표)다. 즉 **시간표는
공식 경로로 얻을 수 있고, 좌석과 예약은 얻을 수 없다**는 v0.3 이후의 판단이
그대로 유지된다.

### 2-2. 코레일 공식 "예약대기"

| 항목 | 상태 | 내용 |
|---|---|---|
| 기능 존재 | **확인됨** | 매진 열차를 대상으로 하는 공식 예약대기 기능이 있다 |
| 신청 기한 | **잠정 정보** | 검색 결과상 출발 2일 전까지. **공식 안내 원문을 대조하지 못했다** |
| 반환 좌석 배정 기준 | **잠정 정보** | 검색 결과상 빈 좌석이 생기면 신청 순서대로 자동 배정. 배정 상세 기준(좌석등급·인원·구간 부분일치 처리 등)은 원문을 확인하지 못했다 |
| 알림 | **잠정 정보** | 좌석 배정 시 문자 등으로 안내된다는 설명. 채널·시점의 정확한 규정은 미확인 |
| 신청 경로 | **확인됨** | 코레일톡 앱, 레츠코레일(웹) |
| 순서 규칙 | **잠정 정보** | 신청 순서대로 배정하되 2매 이상은 순서가 다소 바뀔 수 있다는 설명 |
| API 제공 여부 | **미확인** | 예약대기를 외부에서 신청·조회하는 공개 API는 확인하지 못함 |

> 신청 기한과 배정 기준은 사용자에게 안내하기 전에 코레일 공식 안내 화면에서
> 반드시 대조해야 한다. RailFlow 화면에 이 수치를 단정적으로 쓰지 않는다.

**이것이 이번 조사에서 가장 중요한 발견이다.** 취소표를 잡기 위해 반복
조회하는 것은 운영자가 이미 공식 기능으로 대체해 둔 행위다.

### 2-6. 요청 제한·중복 방지·결제기한·취소 정책

| 항목 | 상태 |
|---|---|
| 공개된 API 요청 제한 | **원문 확인 필요** — 안내상 "무료, 일일 제한 없음"으로 검색되지만 원문을 대조하지 못했다. 제한이 없다는 전제로 조회 주기를 정하지 않는다 |

`lib/autobook/rate-limit.ts` 의 모든 정책이 `basis: "conservative_default"`
인 이유가 이것이다. 공식 수치를 확인하면 `official_documented` 로 바꾼다.

## 3. KayRail과 RailFlow의 구조 차이

사용자가 KayRail 화면에서 실제 좌석 상태·자동예약 진행·시도 횟수·만료시간이
표시되는 것을 확인했고, 공개 안내상 서버에서 자동예약이 진행되며 코레일 계정
연동이 필요하고 좌석 확보 후 사용자가 코레일+에서 직접 결제한다고 한다.

| | KayRail (공개 안내 기준) | RailFlow (v0.9) |
|---|---|---|
| 감시 위치 | 서버 | 서버 (동일 구조로 설계) |
| 계정 | 코레일 계정 연동 필요 | **연동 방식 미확인 → 비활성.** 비밀번호를 받지 않는다 |
| 좌석 확보 | 서버가 예약 | **승인된 연동이 없어 미구현(Stub)** |
| 결제 | 사용자가 코레일+에서 직접 | 동일 (결제 자동화 안 함) |
| 공식 서비스 여부 | **비공식** | 비공식 |
| 연동 방식 | **공개되지 않음** | 공개·승인된 경로만 사용 |

**KayRail이 작동한다는 사실은 기술적 가능성의 근거일 뿐이다.** 동일 방식의
이용이 허용된다는 뜻도, 비공개 연동을 사용할 권한이 있다는 뜻도 아니다.
그 서비스가 어떤 경로를 쓰는지 우리는 모르고, 알아내려 시도하지도 않았다
(앱 트래픽 가로채기·디컴파일·세션 추출을 하지 않았다).

## 4. 이 조사가 v0.9 구현에 미친 영향

1. `official-approved` Provider 를 **Stub 으로 남겼다.** 허용된 요청·응답
   명세와 이용 권한을 확인하지 못했기 때문이다(지침 §3).
2. **계정 연결을 비활성화했다.** 공식 OAuth·API credential·단기 세션 중
   어느 것도 확인하지 못했으므로 우선순위 4번("실제 Provider 미구현")이다.
3. **요청 제한 정책을 전부 보수적 기본값으로 두었다.**
4. 화면은 `공식 연동 준비 중` 을 표시하고, Mock 결과를 실제처럼 보여주지
   않는다.

## 5. 이 조사의 한계

- **코레일·SR 공식 페이지 본문을 직접 열지 못했다.** 이 작업 환경의 네트워크
  정책이 `data.go.kr`, `info.korail.com` 등으로의 접근을 차단한다. 우회하지
  않았다.
- 따라서 위 내용은 **공개 웹 검색 결과에 근거한 것**이며, 공식 문서 원문
  대조를 거치지 않았다. "확인됨"도 그 한계 안에서의 확인이다.
- **검색 결과 요약을 공식 원문 확인으로 바꿔 적지 않았다.** 기한·횟수·시행범위
  같은 수치는 `잠정 정보` 또는 `원문 확인 필요` 로 내렸다. §1-1의 다섯 가지만이
  외부 조사와 무관하게 확정이다.
- 이용약관 원문, 판매대행 계약 조건, 예약대기 API 존재 여부는 사용자가
  직접 확인하거나 고객센터에 문의해야 한다.

## 5-1. v0.11 재조사 결과 (2026-10-01)

**이 문서의 등급은 v0.11에서도 올라가지 않았다.** 2026-10-01에 공식 원문 호스트 11개에
각각 1회 접근을 시도했고 **전부 프록시에서 차단**됐다(`data.go.kr`, `info.korail.com`,
`korail.com`, SRT 예매 호스트, `letskorail.com`, `data.kric.go.kr`, `openapi.kric.go.kr`,
`molit.go.kr`, `kr.or.kr` 등). curl 과 WebFetch 둘 다 같은 결과였다. 우회하지 않았다.

따라서 이 문서의 `잠정 정보`·`원문 확인 필요` 항목은 **그대로 남는다.**

v0.11에서 새로 나온 단서 두 가지 — 둘 다 **잠정 정보**이며 원문 미열람이다.

1. **공식 제휴·판매대행 채널이 실재할 가능성.** 코레일이 정부·민간기업 홈페이지·앱에서
   승차권을 구매할 수 있는 '전용 웹'을 개발했다는 보도자료가 검색된다. 다만 설명상
   "표준화된 **화면**"이어서, 좌석 상태를 **데이터로** 주는 연동인지는 미확인이다.
   이것이 v0.11의 가장 유망한 후보다.
2. **매크로 탐지 운영.** 코레일이 2026년 7월 매크로 탐지 솔루션을 도입해 접속 패턴을
   실시간 분석하고 **로그인·승차권 조회 단계부터** 차단한다는 설명이 검색된다. 이는
   `docs/adr/0003-abandon-browser-agent.md` 에 기록된 이 프로젝트의 실제 관찰과 일치한다.
   다만 **약관에 자동화 금지 조항이 있는지 자체는 여전히 미확인이다** — 금지 조항 부재를
   허용으로 읽지 않는다.

판정과 후속 절차는 [V0.11-OFFICIAL-PROVIDER-GATE.md](./V0.11-OFFICIAL-PROVIDER-GATE.md).

## 6. 다음에 확인해야 할 것

1. **코레일 공식 "예약대기"로 충분한가?** 사용자의 실제 필요(동탄→울산
   특정 열차)를 공식 기능이 이미 해결한다면, 자동 조회를 만드는 것보다
   그쪽으로 안내하는 것이 낫다.
2. 코레일 파트너·판매대행 창구의 실재와 신청 조건 (고객센터 1544-7788)
3. 통합 이후 동탄→울산(통도사)의 실제 예매 경로
4. 자동화 프로그램 이용에 관한 약관 조항 원문

**이 중 1번이 먼저다.** 허용된 경로가 이미 있는데 새로 만드는 것은 순서가
틀렸다.

v0.11 보강: 1번을 확인할 **구체적 절차**를 만들었다
([V0.11-OFFICIAL-PROVIDER-GATE.md](./V0.11-OFFICIAL-PROVIDER-GATE.md) §5). 핵심 쟁점은
예약대기 신청이 **출발 2일 전까지**만 가능한지다(잠정) — 그렇다면 출발 직전 취소표 구간은
공식 기능이 비어 있고, 그 구간이 바로 운영자가 자동 조회를 차단하는 구간이다. 공식 기능이
비어 있다는 사실이 그 빈칸을 자동화로 채워도 된다는 뜻은 아니다.
