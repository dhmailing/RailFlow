# RailFlow Android 읽기 전용 실험 — 작업 규칙

이 문서는 `android/` 디렉터리 안의 작업에만 적용된다. 저장소 루트의
`CLAUDE.md` 가 상위 규칙이며, 아래 §3 에 적은 예외 한 건을 뺀 나머지는
그대로 유효하다.

## 1. 이 실험의 범위

최종 목표는 바뀌지 않았다.

> 사용자가 공식 철도 앱에서 **직접 로그인** → 대상 열차 선택 → 잔여좌석
> 반복 확인 → 조건에 맞는 예약 확보 → 알림 → **사용자가 공식 앱에서 직접
> 결제.**

이번 첫 버전이 실제로 하는 일은 그중 일부다.

| 범위 안 | 범위 밖(이번에 구현하지 않음) |
|---|---|
| 설치 가능한 Android 앱 | 실제 예약 생성 |
| 검색·자동예약·마이페이지 화면 | 반복 조회(폴링) |
| 후보 열차·예약 조건의 로컬 저장 | 결제 |
| 사용자가 직접 켠 **읽기 전용** 화면 정보 확인 | 자동 클릭·제스처·새로고침 |
| 결과 표시·알림·즉시 중단 | 백그라운드 상시 실행 |

## 2. 하지 않는 것

루트 `CLAUDE.md` 의 「하지 않는 것」을 그대로 따른다. Android 맥락에서
구체적으로 금지되는 것을 덧붙인다.

- SRT·코레일 등 **공식 앱의 내부 API·통신·인증을 분석하거나 복제하지
  않는다.** 트래픽 가로채기, 인증서 핀 해제, 리버스 엔지니어링을 하지
  않는다. 참고는 공개 화면과 사용자가 직접 제공한 화면으로 한정한다.
- 자동 클릭·제스처·스와이프·새로고침을 수행하지 않는다. 접근성 서비스는
  **읽기만** 한다.
- 접근 제한·CAPTCHA·대기열·속도 제한을 우회하지 않는다. 탐지 회피,
  보안 기능 해제, 루팅을 하지 않는다.
- 철도 계정 비밀번호·OTP·쿠키·세션을 입력받거나 저장하지 않는다.
- 화면 전체 원문과 스크린샷을 저장하거나 외부로 전송하지 않는다.
- 접근성 서비스를 **장애인 지원 도구라고 허위 선언하지 않는다.** 선언문에
  실제 용도를 그대로 적는다.
- 직접 입력한 열차를 검증된 실제 열차로 취급하지 않는다.
- 권한 허용을 실제 조회 성공으로 표시하지 않는다.
- 값이 없거나 열차 식별이 불명확하면 **상태 불명**으로 표시한다. 매진이나
  예약 가능으로 추정하지 않는다.
- 한 화면에 있는 서로 다른 열차의 번호·시각·좌석 문구를 합치지 않는다.
- 웹을 WebView 로 감싼 앱으로 대신하지 않는다.
- 읽기에 필요한 정보가 접근성 노드에 없으면 **읽기 불가**로 보고한다.
  OCR·화면 캡처·좌표 클릭·다른 우회 수단으로 전환하지 않는다.

## 3. ADR 0003(브라우저 Agent 폐기)과의 관계

루트 `CLAUDE.md` 와 `docs/adr/0003-abandon-browser-agent.md` 는 **공식 예매
화면을 브라우저로 조작하는 방식을 폐기**했다. 폐기 사유는 두 가지였다.

1. 서버에서 헤드리스 브라우저로 공식 화면을 열어 **조작**했고, 그것이
   자동화된 요청으로 판정돼 접속이 제한됐다.
2. 되살리려면 탐지 회피가 필요했고, 그것은 하지 않기로 했다.

이번 Android 실험이 그 결정에 저촉되지 않는 이유는 **조작하지 않기
때문이다.** 차이를 혼동하지 않도록 명시한다.

| | 폐기된 브라우저 Agent (ADR 0003) | 이번 Android 읽기 전용 실험 |
|---|---|---|
| 실행 주체 | RailFlow 서버 | 사용자 기기, 사용자가 켠 세션에서만 |
| 로그인 | 서버가 사용자 자격증명으로 수행 | **사용자가 공식 앱에서 직접** |
| 화면 조작 | 클릭·입력·새로고침 수행 | **하지 않음.** 읽기만 |
| 요청 발생 | 서버가 공식 서버로 요청을 보냄 | 앱이 공식 서버로 요청을 보내지 않음 |
| 세션 보관 | 서버가 쿠키·세션 보관 | 보관하지 않음 |
| 중단 | 서버 정책에 의존 | 사용자가 즉시 중단, 권한 해제 시 즉시 정지 |

**이번에 인정하는 예외는 한 건뿐이다.** 루트 규칙의 "공식 예매 화면을
브라우저로 조작하는 방식"은 금지된 상태로 남고, 그와 별개로 **사용자가
자신의 기기에서 직접 켠 읽기 전용 접근성 관찰**을 허용한다. 이 예외는
아래를 전부 만족할 때만 유효하다.

- 사용자가 앱 안에서 목적·읽는 정보·보관 여부를 읽고 직접 활성화했다.
- 사용자가 시작한 관찰 세션 중이다.
- 쓰기 동작(클릭·제스처·입력)을 하나도 하지 않는다.
- 대상 앱 패키지와 대상 화면이 **확인된** 경우에만 처리한다.

**이 승인에 포함되지 않은 것:** 접근 제한 우회, 비밀번호 저장, 반복 조회,
실제 예약, 결제 자동화. 기존 검증(`scripts/verify-*.cjs`)을 삭제하거나
검사 범위를 느슨하게 만들지 않는다.

## 4. 처리 대상과 제외 대상

**처리한다**: 확인된 대상 앱 패키지의, 확인된 검색 결과 화면에 있는 열차
번호·출발/도착 시각·좌석 표시 문구.

**처리하지 않는다**: 대상 앱 외의 모든 앱, 로그인·인증 입력창, 결제 화면,
개인정보 화면, 비밀번호 필드, 그 외 용도가 확인되지 않은 화면. 이들은
노드를 읽지 않고 즉시 건너뛴다.

**패키지 이름을 추측하지 않는다.** 대상 패키지는 사용자가 확인해 준 값만
설정에 들어간다. 이름이 비슷하다는 이유로 추가하지 않는다.

## 5. 권한

첫 버전이 요청하는 권한은 둘뿐이다.

- **접근성 서비스** — 읽기 전용 관찰
- **알림** — 결과·오류·중단 안내

요청하지 않는다: 화면 캡처, 다른 앱 위에 표시, 알림 읽기, 전체 파일 접근,
연락처, SMS, 위치, 카메라, 마이크, 배터리 최적화 예외.

권한이 거부돼도 검색·자동예약·마이페이지 화면은 그대로 쓸 수 있어야 한다.

## 6. 보고 규칙

- 테스트 화면(자체 진단) 결과를 **실제 좌석 조회로 보고하지 않는다.**
- 공식 철도 앱에 대한 검증을 수행하지 않았으면 `NOT RUN` 으로 남긴다.
- 빌드 실패를 성공으로 보고하지 않는다. APK 가 만들어지지 않았으면
  "소스만 작성" 이라고 적는다.
- SRT 트리거 앱 등 타사 앱의 **현재 동작 여부를 직접 검증했다고 보고하지
  않는다.** 사용자 관찰은 사용자 관찰로 적는다.
- 가상 데이터와 실제 데이터를 화면과 보고 양쪽에서 구분한다.
